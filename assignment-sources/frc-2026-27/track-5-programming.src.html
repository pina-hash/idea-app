Module 2.1

Run motors and sensors with Phoenix 6 and REVLib

2 hrs

You will: Add vendor libraries and drive CTRE and REV devices on a named CAN bus.

  1. Install vendor libraries per project from the WPILib Vendor Dependencies view.
  2. Use Phoenix 6 26.3.0 and REVLib 2026.0.5 on the 2026 roboRIO robot.
  3. Use Phoenix 6 26.70.0-alpha-2 and REVLib-2027 JSON on the 2027 SystemCore robot.
  4. Declare the CAN bus every time: `new TalonFX(0, new CANBus(CANPort.CAN_S2))`.

The project builds with both vendor libraries, and a test motor spins in the direction and units you expect.

More detail
  • Know who makes what: Phoenix 6 runs CTRE devices (Talon FX, Kraken, CANcoder, Pigeon 2); REVLib runs REV devices (SPARK MAX, SPARK Flex, Color Sensor V3, Servo Hub).
  • To install, click Install in that view, or run WPILib: Manage Vendor Libraries, then Install new libraries (online), and paste the JSON URL.
  • On the 2026 robot, Phoenix 6 comes from the frc2026 JSON below. Never paste a 2025 or older season's link.
  • The CTRE Phoenix 6 docs describe 2026.
  • 2027: get Phoenix 6 from the CTR-Phoenix page, and match both libraries to your WPILib alpha with the SystemcoreTesting table.
  • SystemCore has five CAN buses, so every device names its bus.
  • In REVLib, use `setSetpoint()` instead of the deprecated `setReference()`.
  • REVLib 2027 alpha-7 removes SPARK conversion factors, so convert units in your own code.
  • Reconnect and rebuild at least every 30 days, or the online vendor cache clears.

Module 2.2

Structure code with command-based

3 hrs

You will: Split robot code into subsystems and commands, and bind commands to controller buttons.

  1. Read the command-based overview: Commands v2 (since 2020) and v3 (new for 2027).
  2. Learn v2 first; it works on both robots and nearly every example and library uses it.
  3. Make one subsystem for an intake; its motors and sensors live only inside it.
  4. Write two commands for it (run in, stop) and bind them to buttons with triggers.
  5. Test it in simulation, then commit your work.

Pressing a button in simulation runs the intake command, and releasing or pressing stop ends it.

More detail
  • A subsystem runs only one command at a time; a new command that requires it interrupts the old one.
  • 2027 v2 changes: `Command.schedule()` is deprecated and `Subsystem.idle()` is added.

Module 3.3

Migrate code to WPILib 2027

4 hrs

You will: Move a 2026 project to WPILib 2027 and find both the loud and the silent breaking changes.

  1. Copy the project first; never migrate the 2026 roboRIO robot's only copy.
  2. Import the copy with the 2027 VS Code importer; Java 25 is required.
  3. Fix the loud breaks: `edu.wpi.first` is now `org.wpilib`, CAN classes take a `CANPort`.
  4. Hunt the silent break: `Rotation2d` getters wrap angles, so heading math can change.
  5. Read the New for 2027 and Removed features pages; all of it is still alpha.

The copied project builds on WPILib 2027 and runs in simulation, with a list of every change you made.

More detail
  • More loud breaks: constants are ALL_CAPS, and SmartDashboard, Sendable and SendableChooser become Telemetry, Tunables and Selectable.
  • Wrapped angles compile with no errors and can still make the robot act differently.
  • Removed tools: Shuffleboard and SmartDashboard (use Elastic and AdvantageScope), PathWeaver (use Choreo or PathPlanner), RobotBuilder (no replacement).
  • Everything here is alpha and may change before and after the Jan 9, 2027 kickoff.

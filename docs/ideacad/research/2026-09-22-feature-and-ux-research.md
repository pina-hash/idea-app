# Build IdeaCAD on gestures, not dialogs

IdeaCAD should copy SolidWorks' interaction layer and very little of its breadth. Across every feature SolidWorks documents, its speed comes from five habits: previews that appear before any input, preselection, sticky last-used values, handles and editable callouts in the canvas, and never leaving the canvas to type a number. The tools most praised for learnability (SketchUp, Tinkercad, Plasticity, Shapr3D, Fusion, Onshape) add four more: inference that names what it is about to snap to, typed values during any drag, selection first and then a one-key verb, and direct edits that land in history instead of bypassing it. The vendored Remus kernel is not the constraint. It exposes 312 methods, IdeaCAD calls about 75, and the only requested operations it cannot perform are full-round fillet, a fillet between non-adjacent faces, rib, vertex chamfer, sketch splines and a working smooth loft. Most of those are rigor features or can be built from primitives, and STEP needs one more module vendored at the same revision. The real blocker is inside IdeaCAD: it has no viewport hover pipeline and draws no dimension values in the viewport, and about a third of the mechanics below depend on those two pieces, including dynamic highlight, preview on hover, mate-connector inference, Select Other, click-a-number editing and breadcrumbs. The honest simulation set is exact interference and clearance, a CG and tip-over readout, a spinner-weapon calculator fed by the model's own moment of inertia, one-degree-of-freedom mechanism posing, and closed-form FRC checks. Linear static FEA should wait behind a validation gate, because the only browser solver found is unreleased and GPL-licensed. IdeaCAD's own density rule, which refuses a center of mass for any body without a cited uniform density, limits those physics tools more than the kernel does. The scrubbable timeline is cheap in concept, because a feature history already is a replay script. Deep replays cost 60 to 110 ms each, though, so playback should run from cached meshes rather than from the kernel.

## 1. Launch and documents: open ready to sketch, and keep parts as definitions inside one file

IdeaCAD's front door already lists a student's models as cards with thumbnails, folders, tags, archive and a thirty-day trash, and every new document opens as an empty standalone exact-solid file ([IDEACAD.md](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/docs/IDEACAD.md)). The empty file is the part to improve. SolidWorks ships an option, "Create sketch on new part", that opens a new part with a sketch already active on the Front Plane ([SW Help: Sketch Options](https://help.solidworks.com/2025/English/SolidWorks/sldworks/HIDD_OPTIONS_SKETCH.htm)). Its Rapid Sketch goes further: with any sketch tool active, moving onto a plane or planar face opens a sketch there with no "select plane, click Sketch" ceremony ([SW Help: Rapid Sketch](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_Using_RapidSketch.htm)). NN/g's guidance on empty states in complex applications asks for three things: communicate system status, give a learning cue, and offer a direct pathway to fill the empty area, because in-context help is applied right away and remembered ([NN/g: Empty States](https://www.nngroup.com/articles/empty-state-interface-design/)). **A new IdeaCAD file should therefore open on the three default planes with a one-line cue and two direct actions, "sketch on a plane" and "start from a box" (Ideation).** The box path borrows Tinkercad's first contact, where a primitive is dragged from a panel onto the workplane ([CPL Maker Lab](https://cplmakerlab.github.io/guide/tinkercad-quickstart-guide/)).

The one-file thesis runs straight into SolidWorks' main argument against it. The vendor's own position is that "multibody parts should not replace the use of assemblies," because one part should equal one BOM line and because Move Component, Dynamic Clearance and Collision Detection exist only in assembly documents ([SW Help: Multibody vs Assemblies](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_Multibody_Parts_Vs_Assemblies.htm)). Onshape keeps two tab types in one document. Its Part Studio holds parts that share references, but Onshape warns that modeling every part of an assembly in one Part Studio hurts performance ([Onshape: Part Studios](https://cad.onshape.com/help/Content/PartStudio/part_studios.htm)). Assembly tabs then define degrees of freedom ([Onshape: Assemblies](https://cad.onshape.com/help/Content/assembly.htm)). Fusion puts both into one design, but its joints only work between components, so bodies must be converted first ([CADArtifex](https://cadartifex.com/blogs/fusion-360-joints-explained-rigid-revolute-slider)). **IdeaCAD can resolve the argument inside one file by making every solid a part by default and splitting each part's definition (its own feature history) from its occurrences (placement and joints) (Both).** That split is what makes editing one wheel edit all four, the way SolidWorks increments `<n>` per reuse of one component file ([SW Help 2026: Assembly tree](https://help.solidworks.com/2026/English/SolidWorks/sldworks/c_featuremanager_design_tree_assembly.htm)). "Make unique" becomes the one-file version of SolidWorks' "save instances as a new file" ([SW Help: Other Assembly Techniques](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_other_assembly_techniques.htm)). Today a mate names two bodies in the same document, and a part reused across documents is a duplicate rather than a link ([IDEACAD.md](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/docs/IDEACAD.md)). Keeping that cross-document rule while adding in-file instancing costs nothing in honesty.

Per-part histories are also a performance requirement, not only a modeling nicety. IdeaCAD measured a forty-feature document: editing the newest feature replays in 3 to 4 ms, but a deep edit replays from the base in 63 to 111 ms. Twelve cached checkpoints grew kernel memory from 2.8 MB to 25.0 MB, and the kernel cannot discard a single checkpoint without dropping every later one ([IDEACAD.md](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/docs/IDEACAD.md)). A robot with twenty parts in one shared feature list would replay every part on every early edit. With per-part lists, a deep edit costs one part's replay (an inference from the measured numbers and Onshape's warning). Onshape's named, read-only versions with compare and restore ([Onshape: Versioning](https://cad.onshape.com/help/Content/Document/versions_and_history.htm)) mainly serve teachers and rigor. IdeaCAD's durable operation log already survives reopening, so named versions can come later. Configurations and design tables serve product families, not ideation, and should be declined.

| Mechanic | Call | Serves | Kernel |
|---|---|---|---|
| New file opens sketch-ready with cue and two actions | Adopt | Ideation | None |
| Every solid is a part; definition vs occurrence; make unique | Adapt (Fusion model) | Both | Per-part replay keeps edits local |
| Named versions, compare, restore | Defer | Rigor | None |
| Configurations, design tables | Decline | Rigor | None |

## 2. Sketching: guess intent while drawing, and let one typed number make everything real

SolidWorks sketching is fast because it guesses intent as you draw. Inference lines are dotted guides to existing geometry, and the pointer changes shape to show the relation it will create (horizontal, vertical, coincident, midpoint, perpendicular, tangent). "If you click to accept the sketch entity while the relation is displayed, the relation is added automatically," and holding Ctrl suppresses automatic relations for the moment ([SW Help: Inferencing](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_Inferencing.htm); [SW Help: Automatic Relations](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_Using_Automatic_Relations.htm)). SketchUp makes the same feedback more legible. Axis alignment is colored red, green and blue, magenta means parallel or perpendicular to existing geometry, and each of fourteen point inferences shows a tooltip naming the snap. The arrow keys lock an axis, and Shift locks the current inference ([SketchUp: Drawing Basics](https://help.sketchup.com/en/sketchup/introducing-drawing-basics-and-concepts)). **IdeaCAD should combine the two: SolidWorks' click-to-commit relations plus SketchUp's colored, named feedback and keyboard locks (Ideation).** The named tooltip is what makes it work without a tutorial, because the tool says what it is about to do.

Four drawing mechanics carry most of the speed. In click-click mode, Line and Arc chain segments, a double-click ends the chain while keeping the tool, and Esc releases it ([SW Help: Sketch Modes](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_Sketch_Modes.htm)). Autotransitioning turns the next segment into a tangent arc when the pointer returns to the last endpoint, and A toggles line and arc ([SW Help: Autotransitioning](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_Autotransitioning.htm)). Numeric input shows length fields beside a rectangle after the first click, with Tab to move between them and Enter to finish ([SW Help: Numeric Input](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_numeric_sketch_input.htm)). SketchUp's Measurements box is the stronger form: "type a value and press Enter," repeatable, with absolute and relative coordinates, and never a dialog ([SketchUp: Drawing Basics](https://help.sketchup.com/en/sketchup/introducing-drawing-basics-and-concepts)). **Typed entry during any draw, with no mode switch, is the one sketching mechanic IdeaCAD must not ship without (Ideation).** Shapr3D shows the cost of missing it. Its docs say "there is no explicit dimension tool," dimensions appear when geometry is selected ([Shapr3D: 2D sketch tools](https://support.shapr3d.com/hc/en-us/articles/13079114694684-Introduction-to-2D-sketch-tools-and-settings)), and users report counting grid squares because they "could not find a way to show how far a thing is from the origin" ([Shapr3D Community](https://discourse.shapr3d.com/t/dimensions-while-sketching/21342)).

Two SolidWorks mechanics are unusually well suited to ideation. First, "when you specify the first dimension in a sketch... all entities in the sketch profile automatically scale uniformly" (not angles, and only the first dimension) ([SW Help: Maintaining Proportions](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_maintain_proportion.htm)). **A student draws loosely, types one real size, and the whole sketch becomes real scale (Ideation).** Second, Shaded Sketch Contours shade closed regions, which "makes it easier to tell if a shape is fully closed or not," and a right-click on a shaded region offers Extruded Boss/Base directly ([SW Help: Shaded Contours](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_Shaded_Sketch_Contour.htm)). IdeaCAD already shows region ticks for extrude ([IDEACAD.md](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/docs/IDEACAD.md)). Upgrading the ticks to shaded regions that can be pulled directly joins sketching to Section 3's push-pull. Contour selection, which picks individual regions during Extrude so a partial sketch can drive a feature ([SW Help: Selecting Contours](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_Selecting_Contours.htm)), follows from the same shading. Power Trim trims many entities in one drag across them and can extend along an entity's natural path ([SW Help: Trim](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_Trim_Entities.htm)). Dynamic Mirror mirrors everything drawn after a centerline is picked ([SW Help: Dynamic Mirror](https://help.solidworks.com/2025/English/SolidWorks/sldworks/HIDD_DVE_SKETCH_DYNAMIC_MIRRORING.htm)). Both are cheap Ideation wins. Sketch Fillet chains an Equal relation onto consecutive same-radius fillets instead of dimensioning each one ([SW Help: Sketch Fillet](https://help.solidworks.com/2025/English/SolidWorks/sldworks/HIDD_DVE_SKETCH_FILLET.htm)). That is a good default next to IdeaCAD's existing corner fillet, which already stores two tangent constraints.

Status feedback should be kept and softened. SolidWorks colors under-defined entities blue, fully defined black, unsolvable red, and conflicting yellow, and it says plainly that "it is not necessary to fully dimension or define sketches before you use them to create features" ([SW Help: Geometry Status](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_Sketch_Geometry_Status.htm); [SW Help: Status Conventions](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_Sketch_Status_Conventions.htm)). **Blue-free and black-locked give students a live "what can still move" readout (Both).** The over-definition path should never block. SolidWorks automatically makes a dimension driven when it would over-define a closed profile ([SW Help: Over Defined](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_Resolving_Over_Defined_Sketches.htm)), and IdeaCAD already separates driving from driven values ([IDEACAD.md](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/docs/IDEACAD.md)). The extra dimension should turn gray as "measured" with one sentence, instead of opening a SketchXpert-style solution dialog ([SW Help: SketchXpert](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_SketchXpert.htm)). Override Dims on Drag, which updates the driving dimension at the end of a drag ([SW Help: Override Dims](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_Override_Dims_on_Drag_Move.htm)), is the more intuitive default for ideation. Help does not state SolidWorks' own default. Entry and exit should follow SolidWorks too: the view auto-rotates normal to the sketch, keeping changes leaves it there, and discarding them restores the prior view ([SW Help: Sketch Options](https://help.solidworks.com/2025/English/SolidWorks/sldworks/HIDD_OPTIONS_SKETCH.htm)). A double-click in empty space exits when no tool is active ([SW Help: Exiting Sketches](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_Exiting_Sketches.htm)).

On the kernel, the 2D constraint solver (`gcsAddPoint`, `gcsAddLine`, `gcsAddArc`, `gcsAddCircle`, `gcsAddConstraint`) has no spline entity, which is why IdeaCAD lists splines as not built ([upstream remus_wasm.d.ts](https://github.com/esaueng/remus/blob/9307e73d880ed824b2b62e44c4a1beb9d5d7b787/crates/wasm/pkg/remus_wasm.d.ts); [IDEACAD.md](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/docs/IDEACAD.md)). The kernel can build NURBS edges outside the solver (`makeNurbsEdge`, `interpolatePoints`). An unconstrained "freeform curve" drawn through clicked points is therefore possible, but it would not take relations (inferred, needs a spike). The alternative, FreeCAD's planegcs compiled to WASM, supports B-splines but is LGPL-2.1 ([planegcs](https://github.com/Salusoft89/planegcs)). The kernel also exposes polygon helpers (`fillet2d`, `chamfer2d`, `offsetPolygon2d`, `polygonBoolean2d`), which make Offset Entities and region math cheap. Decline conics, parabolas, equation-driven curves, belt and chain blocks, Pierce, Merge, Equal Curvature and Fully Define Sketch as Rigor ([SW Help: Sketch Entities](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_sketch_entities_top.htm)).

| Mechanic | Call | Serves | Kernel |
|---|---|---|---|
| Rapid Sketch on hover over a face; auto-normal view, restore on cancel | Adopt | Ideation | None; needs hover pipeline |
| Named colored inference, click-to-commit, Ctrl suppress, arrow locks | Adopt | Ideation | 2D solver constraints exist |
| Chained drawing, line-to-arc on A, typed values mid-draw | Adopt | Ideation | None |
| First dimension rescales sketch | Adopt | Ideation | Solver re-solve |
| Shaded closed regions, pull a region directly | Adopt | Ideation | `polygonBoolean2d` for regions |
| Blue/black status; extra dimension auto-driven, gray | Adapt | Both | None |
| Power trim drag, dynamic mirror, equal-chained sketch fillets | Adopt | Ideation | None |
| Splines | Defer; freeform NURBS curve without relations only after a spike | Rigor | No spline in 2D solver |
| Conics, equation curves, SketchXpert, Fully Define | Decline | Rigor | Not needed |

## 3. Part features: pull a region into a solid, and record every drag as a parameter

Instant3D is SolidWorks' closest thing to push-pull, and it is on by default. Selecting a sketch contour shows a drag handle. Dragging extrudes it with a ruler, and **boss or cut is inferred from where the contour is clicked**: a contour on a face defaults to a cut, and one not touching a face defaults to a boss ([SW Help: Instant3D](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_instant3d.htm); [SW Help: Instant3D Sketch Selection](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_sketch_selection_and_existing_geometry.htm)). The ruler "snaps to the ruler increments" only while the pointer is over it and drags freely otherwise. Alt-hovering another face snaps the size to it, and holding M extrudes symmetrically ([SW Help: Rulers](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_instant3d_rulers.htm); [SW Help: Snapping](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_snapping_with_instant3D.htm); [SW Help: Midplane](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_using_the_midplane.htm)). Single-clicking a dimension opens Quick Edit. A handle that turns black means the feature is locked, and dragging a mirrored or patterned instance drives the seed ([SW Help: Modifying in Instant3D](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_I3D_modifying_features.htm); [SW Help: Instant3D Overview](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_instant3d_functionality.htm)). **Because Instant3D edits the feature's own parameter, history stays parametric; IdeaCAD should keep that property, so every drag writes a dimension value (Ideation).** One SolidWorks gap should not be copied: dragging internal sketch contours in Instant3D "does not support Undo" ([SW Help: Editing Sketches in Instant3D](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_Editing_Sketches_in_Instant3D.htm)).

The faster tools refine the same verb. SketchUp's Push/Pull takes a typed value then Enter, repeats the last distance on a double-click, and infers height from another parallel face. Pushing through to an opposite face cuts a hole ([SketchUp: Push/Pull](https://help.sketchup.com/en/sketchup/pushing-and-pulling-shapes-3d)). Plasticity puts the booleans on single keys while an extrude is live (Q union, W difference, Shift+E intersect, S symmetric), and its 2026.1 release made Tab enter a precise distance across Move, Rotate, Scale and Extrude ([Plasticity: Extrude](https://doc.plasticity.xyz/solid/extrude); [Plasticity 2026.1](https://doc.plasticity.xyz/release-notes/whats-new-2026.1)). Tinkercad teaches constructive solid geometry without the term: any shape can be toggled to Hole, and grouping subtracts it ([CPL Maker Lab](https://cplmakerlab.github.io/guide/tinkercad-quickstart-guide/)). Shapr3D's 2024 history makes each direct move "show up as a history step" ([Shapr3D blog](https://www.shapr3d.com/blog/shapr3d-history-based-parametric-modeling)). Its help also warns that direct edits pile up as offset entries that clutter the history ([Shapr3D: Direct vs Parametric](https://support.shapr3d.com/hc/en-us/articles/14030415438748-Direct-vs-Parametric)). **IdeaCAD should record an "up to that face" snap as a relation rather than a baked number, and fold consecutive pushes on the same face into one feature (Ideation).** The folding is a design suggestion, not a documented Shapr3D behavior. IdeaCAD already pushes planar and cylindrical faces through the kernel's journaled `moveFacesJournaled`, and a warm drag measured 4.7 to 7.8 ms, fast enough for one kernel operation per frame ([IDEACAD.md](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/docs/IDEACAD.md)).

Holes, shell and rib are the feature-level ideation wins. SolidWorks recommends Simple Hole for plain holes because it performs better, and keeps Hole Wizard for counterbore, countersink and tapped holes, carrying a size such as M6 across types by default ([SW Help: Holes](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_Holes_Folder.htm); [SW Help: Hole Wizard Match Size](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_hole_wizard_match_size_preserve_settings.htm)). IdeaCAD already has a hole feature with a sourced size chart (ASME B18.2.8 clearance, UNC and metric tap drills) ([IDEACAD.md](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/docs/IDEACAD.md)). **The kernel has no hole operation, but counterbore is a second cylinder fused into the cutting tool and countersink is `makeCone`; revolving one half-section profile gives a single tool with exact analytic faces (Ideation, buildable)** ([Remus d.ts](https://github.com/esaueng/remus/blob/9307e73d880ed824b2b62e44c4a1beb9d5d7b787/crates/wasm/pkg/remus_wasm.d.ts)). Shell with pick-faces-to-open is Stable upstream but takes one thickness ([Remus README](https://github.com/esaueng/remus/blob/9307e73d880ed824b2b62e44c4a1beb9d5d7b787/README.md)). IdeaCAD already shells uniformly, then moves each flat inner face by the difference, measured exact, and refuses curved inner faces by name ([blends.ts](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/src/lib/ideacad/solid/features/blends.ts)). Upstream HEAD adds `shellWithQuality`, which opts in to approximation for NURBS faces ([Remus d.ts at HEAD](https://github.com/esaueng/remus/blob/cb13b53f5a40a56e78ae2efd4f7798280e2e0cc2/crates/wasm/pkg/remus_wasm.d.ts)). SolidWorks' rib extrudes an open or closed contour to fill material "between the contour and an existing part" ([SW Help: Rib](https://help.solidworks.com/2025/English/SolidWorks/sldworks/HIDD_FEAT_RIB.htm)). A student sketches one line and gets a gusset, which makes it a high-value Ideation feature. The kernel has no extend-to-body, so IdeaCAD refuses rib today ([extra.ts](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/src/lib/ideacad/solid/features/extra.ts)). A construction is plausible: offset the line by half the thickness into a strip, extend it past the bounding box, extrude it, intersect it with the region between the line and the body's `section`, computed with `polygonBoolean2d`, and fuse. `convexHull` of the body's vertices is a one-call fill region that is correct for a convex corner such as an L-bracket but overfills non-convex bodies. **Rib needs a measured spike before a lane depends on it.**

Sweep and loft deserve narrow, honest versions. SolidWorks' rules say the path must intersect the profile plane and nothing may self-intersect ([SW Help: Sweep Rules](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_sweep_rules.htm)). Those rules should become proactive hints in IdeaCAD, not failure messages. IdeaCAD's sweep uses `sweepAlongEdges`, which fits a curve through sampled points. On a line-plus-arc path it measured 434 planar faces and a volume 2% under the analytic value ([extra.ts](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/src/lib/ideacad/solid/features/extra.ts)). **The cheap win is `sweepWithOptions(face, edge, 'rmf', [], segments, 'smooth')` for a single path edge, which OpenZCAD uses to get an exact cylinder on a line path** ([OpenZCAD profile builders](https://github.com/esaueng/OpenZCAD/blob/3add9e4b8f230479bae866d00036693ce1db6585/packages/kernel-adapter/src/exact-profile-builders.ts)). Multi-segment exact paths would need IdeaCAD code to join lines and arcs, read as rational NURBS through `getNurbsCurveData`, into one knot vector, since the kernel has no curve-join call (inferred). Loft is ruled only. `loftSmooth` through three profiles returned a negative volume and failed validation in this build. Profiles with holes are refused, and vertex counts must match ([extra.ts](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/src/lib/ideacad/solid/features/extra.ts); [Remus README](https://github.com/esaueng/remus/blob/9307e73d880ed824b2b62e44c4a1beb9d5d7b787/README.md)). OpenZCAD documents a silent failure that matters here. A loft with an apex point and a sweep with a rail both lose their exact surfaces, going to 66 and 74 planes and 0.64% and 2.02% short of the analytic volume, while "`validateSolid` passes, no warning is emitted" ([OpenZCAD profile builders](https://github.com/esaueng/OpenZCAD/blob/3add9e4b8f230479bae866d00036693ce1db6585/packages/kernel-adapter/src/exact-profile-builders.ts)). **Every sweep and loft result should be checked for surface types and labeled "approximated" when faceted (Rigor, but cheap).**

Patterns and mirror are ideation-critical. SolidWorks counts the seed in the instance count, lets users click instance markers to skip them, and highlights seed and instances in different colors ([SW Help: Linear Pattern](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_Linear_Patterns_Overview.htm); [SW Help: Colors](https://help.solidworks.com/2025/English/SolidWorks/sldworks/HIDD_OPTIONS_SYSTEM_COLORS.htm)). IdeaCAD builds patterns with `copyAndTransformSolid` per copy rather than the kernel's compound-returning `linearPattern` and `circularPattern`, whose circular form takes no center point or angle ([core.ts](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/src/lib/ideacad/solid/features/core.ts)). That is the right choice, since skip and per-instance naming need separate solids. Draft is Stable upstream for planar faces only, and curved faces, holed targets and cavities are refused ([stability matrix](https://github.com/esaueng/remus/blob/9307e73d880ed824b2b62e44c4a1beb9d5d7b787/docs/production-readiness/stability-matrix.md)). IdeaCAD already has it. Parting-line and step draft are Rigor and not exposed. Helical sweep can make true threads, but cosmetic threads should stay cosmetic for cost.

## 4. Fillets, chamfers and curvature: one pick should expand into the right edge set

Most of SolidWorks' fillet speed comes from how edges get selected, not from its four fillet types. Tangent propagation extends a pick across a smooth chain. A pop-up "selection accelerator" toolbar, dating to 2013, offers edge-set expansions after one pick, and "hovering over the different icons will allow you to preview the different edges that would be selected" ([SW Help: Constant Size Fillets](https://help.solidworks.com/2025/English/SolidWorks/sldworks/r_constant_size_fillets.htm); [SW What's New 2013](https://help.solidworks.com/2013/english/whatsnew/c_edge_toolbar_fillets.htm); [TriMech](https://store.trimech.com/blog/using-the-ghost-edge-selection-pop-up-toolbar-in-solidworks)). Right-click Select Loop picks a face's boundary with a flip handle, and Select Tangency stops at the first non-tangent entity ([SW Help: Contextual Selection](https://help.solidworks.com/2025/English/SolidWorks/sldworks/r_contextualselection.htm)). **The accelerator is the most transferable idea for a novice fillet tool, because it turns "know the selection command names" into "recognize the picture" (Ideation).** IdeaCAD should offer tangent chain, face loop with flip, all edges of this feature, all convex, all concave, and all edges of the body, each previewed on hover. The exact option list of SolidWorks' toolbar was not found in any fetched source. IdeaCAD already has tangent propagation, computed in code because the kernel has no tangency query, and face-to-all-its-edges selection ([blends.ts](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/src/lib/ideacad/solid/features/blends.ts)). The kernel's `edgeToFaceMap`, `adjacentFaces` and `sharedEdges` make convex and concave classification buildable (inferred).

The fillet PropertyManager "remembers its last used state," and a pushpin keeps it open to apply several fillets in a row ([SW Help: Fillet PropertyManager](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_fillet_propertymanager.htm)). Ctrl-drag copies a fillet to another edge ([SW Help: Modifying in Instant3D](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_I3D_modifying_features.htm)). Both are Ideation adopts. SolidWorks' own ordering advice is to add larger fillets before smaller ones, drafts before fillets, and fillets before shelling, with cosmetic fillets last ([SW Help: Fillet Overview](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_fillet_overview.htm); [SW Help: Shells](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_Shells_Folder.htm)). FilletXpert "automatically reorders fillets when required," which proves the approach ([SW Help: FilletXpert](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_FilletXpert_Overview.htm)). **IdeaCAD could enforce that order as a guardrail, suggesting a reorder when a student fillets after shelling, rather than teaching it (Both).**

The kernel turns fillet failure into a teaching moment. Remus refuses a radius it cannot fit as a typed error that names the edge and the limit, never as a partial result. OpenZCAD shows the message shape: "requested radius 30, available radius 18" ([Remus README](https://github.com/esaueng/remus/blob/9307e73d880ed824b2b62e44c4a1beb9d5d7b787/README.md); [OpenZCAD edge modifiers](https://github.com/esaueng/OpenZCAD/blob/3add9e4b8f230479bae866d00036693ce1db6585/packages/kernel-adapter/src/exact-edge-modifiers.ts)). **IdeaCAD should parse that limit and offer "largest radius that fits here: 18" as a one-click fix (Ideation).** OpenZCAD also found that a box with all twelve edges selected refuses as `unsupported-vertex-blend` at every radius from 9 up. Corner-heavy selections will fail, so the refusal sentence should say which corners. Blend editing is a quiet direct-modeling win: `getBlendRegion` returns a constant-radius region and its radius, and `resizeBlend` changes it, with zero restoring the sharp edge. Clicking any existing round, including one on an imported body, and dragging its radius is therefore buildable, though resize-blend is Experimental upstream ([stability matrix](https://github.com/esaueng/remus/blob/9307e73d880ed824b2b62e44c4a1beb9d5d7b787/docs/production-readiness/stability-matrix.md)).

The rigor tier splits by kernel support. **Variable radius is exposed and already built** through `filletVariable` with constant, linear and S-curve laws. Unknown laws are silently turned into a constant radius, so validate the law before calling ([OpenZCAD variable blends](https://github.com/esaueng/OpenZCAD/blob/3add9e4b8f230479bae866d00036693ce1db6585/packages/kernel-adapter/src/exact-variable-blends.ts)). It is Rigor and belongs behind a disclosure. Face fillet between non-adjacent faces is not supported on a solid: `faceFaceBlend` returns a standalone sheet between two planar faces, and body re-limitation is Unqualified upstream ([stability matrix](https://github.com/esaueng/remus/blob/9307e73d880ed824b2b62e44c4a1beb9d5d7b787/docs/production-readiness/stability-matrix.md)). Decline it. Full round is borderline Ideation, because it needs no number and instantly rounds the end of a rib or tab ([SW Help: Full Round](https://help.solidworks.com/2025/English/SolidWorks/sldworks/r_Full_Round_Fillets.htm)). The kernel has no three-face blend. Two half-thickness fillets on a wall's cap edges will be refused ("two bands consuming one thin wall... return transactional `CliffEncountered`"). A construction for straight parallel walls is plausible: read wall thickness from `getOpposingPlanarFacePairs`, cut the cap slab, and fuse a cylinder of radius t/2. It needs a spike. Chamfer distance-distance and distance-angle are built. Switching the angle form to `chamferDistanceAngleWithEvolution` would give it construction-derived face names instead of surface matching. The angle is in radians in practice, while draft and revolve take degrees ([blends.ts](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/src/lib/ideacad/solid/features/blends.ts)). There is no vertex chamfer API, so decline it. Setback, conic and curvature-continuous profiles, hold lines and overflow controls are Rigor and should be declined.

Curvature display should start with tessellation, not analysis overlays. IdeaCAD hard-codes a 0.002 in chord and 0.15 rad angle on every face and body ([engine.ts](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/src/lib/ideacad/solid/engine.ts)). On a 40-inch part that is fine, but on a small printed bracket the 0.15 rad angle facets visible fillets. OpenZCAD uses a size-relative chord of 2e-4 times the part extent, a floor of 1e-5, and 0.06 rad, which keeps the chord "below half a pixel" at a 1,200 px projected radius ([OpenZCAD display tessellation](https://github.com/esaueng/OpenZCAD/blob/3add9e4b8f230479bae866d00036693ce1db6585/packages/kernel-adapter/src/display-tessellation.ts)). **Size-relative deflection is a one-line Ideation win, because round things look round.** `meshQuality` can gate the result. The same code also runs two tessellation passes per body at identical tolerances (lines 522 and 528), which is likely a redundant cost worth measuring (inferred). A curvature map is buildable from `tessellateSolidUV` plus `getFaceCurvature` per vertex, and `getFaceMinRadius` gives the exact smallest radius per analytic face. That is useful for "smallest round a 1/8 in end mill can cut" (Rigor). SolidWorks puts zebra stripes, curvature and draft analysis on its view toolbar ([SW Help: View Toolbar](https://help.solidworks.com/2025/English/SolidWorks/sldworks/r_view_toolbar_display.htm)). These are industrial-design tools and should be declined.

| Edge-set accelerator with hover preview (loop, feature, convex, concave) | Adopt | Ideation | Adjacency queries unused |

## 5. Reference geometry: shortcuts that skip the dialog matter more than the dialog

SolidWorks' plane PropertyManager takes up to three references with eight constraint types, and "the plane status must be Fully defined to create the plane" ([SW Help: Plane PropertyManager](https://help.solidworks.com/2025/English/SolidWorks/sldworks/HIDD_DVE_CREATE_PLANE.htm)). The fast paths are what users actually use. "The software creates the most likely plane based on the entity you select," Ctrl-dragging a plane makes an offset copy, a plane's handles carry an offset ruler, and right-clicking a face offers "Create a Plane Parallel to Screen" with no PropertyManager at all ([SW Help: Creating Planes](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_Creating_Planes.htm); [SW Help: Move, Resize, Copy Planes](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_Move_Resize_and_Copy_Planes.htm); [SW Help: Parallel to Screen](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_right_click_to_create_plane_parallel_to_screen.htm)). "Every cylindrical and conical face has an axis," shown as a temporary axis ([SW Help: Temporary Axes](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_Displaying_Temporary_Axes.htm)). **Temporary axes remove most of the need to create an axis before a revolve or circular pattern (Ideation).** The kernel makes them nearly free, because `getSurfaceType` identifies cylinders and cones and `getAnalyticSurfaceParams` returns their parameters ([Remus d.ts](https://github.com/esaueng/remus/blob/9307e73d880ed824b2b62e44c4a1beb9d5d7b787/crates/wasm/pkg/remus_wasm.d.ts)).

IdeaCAD already builds planes, axes and points from geometry and by construction, with a panel that lists each construction as ready or not with its reason. It uses the area centroid rather than the vertex average for a face center, and it has no viewport hover emphasis ([IDEACAD.md](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/docs/IDEACAD.md)). The recommended change is to collapse the common constructions into gestures. Drag off a face to make an offset plane. Rotate about an edge for an angled plane. Pick two faces for a midplane. Pick a point on a curve for a normal plane, which SolidWorks now files under Perpendicular with "Set origin on curve" ([SW Help: Plane PropertyManager](https://help.solidworks.com/2025/English/SolidWorks/sldworks/HIDD_DVE_CREATE_PLANE.htm)). Onshape's mate connector shows a unifying idea: a local coordinate system inferred on hover at face centroids, edge midpoints and cylinder axis ends, locked with Shift, whose Z axis can serve as an axis input to other features ([Onshape: Mate Connector](https://cad.onshape.com/help/Content/PartStudio/mate_connector.htm)). **One hover-inferred frame could serve as sketch plane, pattern axis and joint origin, so reference geometry and assembly share a single concept (Both).** SolidWorks advises renaming planes to show their purpose ([SW Help: Creating Planes](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_Creating_Planes.htm)). Focus should land in the name field on creation. Coordinate systems, grid systems, center-of-mass points, bounding boxes and numeric reference points (new in 2026) serve export, mass properties and mates ([SW Help: Coordinate Systems](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_Coordinate_Systems.htm); [GoEngineer 2026](https://www.goengineer.com/blog/solidworks-2026-parts-and-features-whats-new)). Defer them as Rigor.

|---|---|---|---|
| Three named default planes plus origin | Already built | Ideation | None |
| Temporary axis on every cylinder and cone | Adopt | Ideation | Surface typing and parameters |
| Drag off a face or Ctrl-drag a plane to offset, with ruler | Adopt | Ideation | None |
| Most-likely plane from one pick | Adopt | Ideation | None |

## 6. Design tree and history: make the rebuild order touchable, then let it play back

SolidWorks' FeatureManager is an ordered rebuild history, and the order it shows is the order features regenerate ([SW Help: Tree Overview](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_featuremanager_design_tree_overview.htm)). A handful of direct manipulations make that history editable without dialogs. Dragging reorders, with a legal or no-drop cursor, and "a reorder operation is legal as long as the parent feature precedes its child feature" ([SW Help: Reordering](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_reordering_features_dragging.htm)). The rollback bar is a draggable line: features below it go gray, new work is inserted at the bar, and its position is saved with the file ([SW Help: Rollback Bar](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_rollback_bar.htm)). Renaming is a slow double-click or F2, and "Name feature on creation" puts focus in the new name ([SW Help: FeatureManager Options](https://help.solidworks.com/2025/English/Solidworks/sldworks/HIDD_OPTIONS_FEATURE_MANAGER.htm)). Hovering a tree item highlights its geometry, and selecting in the viewport scrolls the tree to that item ([SW Help: Tree Response to Selections](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_featuremanager_design_tree_response_selections.htm)). Suppress grays a feature and its children ([SW Help: Suppress](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_Suppress_and_Unsuppress_Features.htm)). **All of these are Ideation adopts; IdeaCAD's tree already has status glyph plus word, inline rename, reorder by buttons or drag, suppress and delete, with every refusal stated in the reducer's own sentence** ([IDEACAD.md](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/docs/IDEACAD.md)).

Three SolidWorks details should be changed rather than copied. Dynamic Reference Visualization draws blue arrows to parents and purple to children on hover, but it is disabled by default ([SW Help: Feature Relationships](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_viewing_feature_relationships.htm)). **IdeaCAD should show those arrows whenever a reorder is refused, because that is exactly when a novice is confused.** Unsuppressing a parent in SolidWorks does not bring back its children, while unsuppressing a child brings back its parent ([SW Help: Suppress](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_Suppress_and_Unsuppress_Features.htm)). That asymmetry is a surprise; restoring dependents by default is simpler. Rolling back to an absorbed sketch requires a "temporarily unabsorbed" dialog ([SW Help: Rollback Bar](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_rollback_bar.htm)). IdeaCAD can keep sketches nested under their features but let the bar stop between a sketch and its feature. SolidWorks also needs a flyout copy of the tree because the PropertyManager takes over the left pane, and that flyout cannot roll back or suppress ([SW Help: Flyout Tree](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_flyout_featuremanager_design_tree.htm)). A layout that never hides the tree during a command avoids the problem. Selection breadcrumbs are a second route to structure. On one selection, a chain appears showing the face, its feature, the sketch that drives it, the part and any parent assembly, each crumb clickable, and "you can hide the FeatureManager design tree and still interact with items" ([SW Help: Breadcrumbs](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_selection_breadcrumbs.htm); [GoEngineer: Breadcrumbs](https://www.goengineer.com/blog/selection-breadcrumbs-in-solidworks-explained)). **Breadcrumbs teach parametric structure to students who never look at the tree (Ideation).** Configurations, Design Binder, Favorites, tags, selection sets, sensors, external-reference symbols and the nineteen-folder visibility matrix are Rigor ([SW Help: FeatureManager Options](https://help.solidworks.com/2025/English/Solidworks/sldworks/HIDD_OPTIONS_FEATURE_MANAGER.htm)). Decline them.

The timeline belongs at the bottom and should never ask the student to choose a mode. Fusion's timeline has play, pause, step and jump-to-ends buttons, a draggable marker that rolls the design back, groups, and a component color swatch per feature ([Product Design Online](https://productdesignonline.com/tips-and-tricks/8-fusion-360-timeline-tips-you-must-know/)). Fusion also has an anti-pattern: "Do Not Capture Design History" switches the whole design to direct modeling with no timeline ([PDO Knowledge](https://knowledge.productdesignonline.com/article/42-what-is-do-not-capture-design-history-in-fusion-360)). Shapr3D avoids the choice by writing direct edits into an optional history panel, where a user can click any step to see it and insert breakpoints to add features earlier ([Shapr3D: Direct vs Parametric](https://support.shapr3d.com/hc/en-us/articles/14030415438748-Direct-vs-Parametric)). **IdeaCAD should never offer a history-off mode (Ideation).**

### The time-lapse should replay cached meshes, not re-run the kernel

Procreate is the clearest precedent for replay as a feature people want. Time-lapse recording "is enabled by default when you create a new canvas," dragging a finger across the canvas scrubs the replay, and export offers full length or a 30-second cut that "cuts the video down to thirty seconds by removing frames" while keeping important moments ([Procreate Handbook: Video](https://help.procreate.com/procreate/handbook/actions/actions-video)). No CAD tool fetched in this research exports a video time-lapse of feature history, so this would be a differentiator rather than a copy. A B-rep feature history already is the replay script, so nothing extra needs recording. The cost profile, though, rules out naive scrubbing. A deep replay costs 63 to 111 ms at forty features, and each kernel checkpoint is a clone of the arena ([IDEACAD.md](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/docs/IDEACAD.md)). **The practical design stores each feature's tessellated output, already produced as packed arrays by `tessellateSolidGroupedBinary`, as a playback frame, so scrubbing swaps meshes at frame rate and only "roll back here and edit" touches the kernel** (inferred from the measured costs). Frames generated after a replay can be cached lazily. For a condensed replay, feature creation should count as an important moment and parameter tweaks should not. Animating the camera to each new feature turns playback into narration. IdeaCAD also keeps a finer-grained durable operation log in which every accepted gesture is one operation ([IDEACAD.md](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/docs/IDEACAD.md)). That gives two replay sources: the operation log shows process (what the student tried, including undone attempts), and the feature list shows structure. For a classroom, process replay doubles as engineering-notebook evidence. A playback longer than five seconds that starts automatically needs pause and stop controls under WCAG 2.2.2 ([W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/)). The video export mechanism itself was not researched.

| Hover highlight both ways; viewport selection scrolls tree | Adopt | Ideation | Needs hover pipeline |
| Parent and child arrows shown on refused reorder | Adapt | Ideation | Dependency DAG exists |

## 7. Dimensions: one smart tool, and every number clickable where it sits

SolidWorks uses one Smart Dimension tool whose type is inferred from what is picked. For point-to-point, angular and circular dimensions, "where you place the text also changes the type." A line gives its length, two lines their angle, a point and a line the perpendicular distance, an arc its radius, and a circle its diameter, and distances to arcs measure to the center by default. Picking an entity, then a centerline, then dragging across the centerline gives a doubled diameter for a revolve profile ([SW Help: Dimensioning a 2D Sketch](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_Dimensioning_a_2D_Sketch.htm)). Instant2D puts drag handles on a dimension with an on-screen ruler, or lets the user click the value and type without opening the Modify dialog ([SW Help: Instant2D](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_Modifying_2D_Sketch_Dimension_Instant2D.htm)). Tinkercad reaches the same place from the other side, with editable dimension boxes around the selected object's handles ([SPO Learning Lab](https://spolearninglab.com/curriculum/software/3d_modeling/tinkercad/tinkercad_ruler.html)). **The shared lesson is that a number should be edited where it is drawn; IdeaCAD's dimension values live in a panel today because guides are polylines, and drawing value text in the viewport is the prerequisite for everything in this section (Ideation)** ([IDEACAD.md](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/docs/IDEACAD.md)).

IdeaCAD's parser already handles the way students actually type numbers. `parseDimension` accepts `1 1/2`, `3/8`, `2"`, `25.4mm` and `45deg`, refuses malformed input with a sentence, and keeps driving values (typed and made true) apart from driven values (shown as measured and never editable) ([IDEACAD.md](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/docs/IDEACAD.md)). SolidWorks shows driven dimensions in gray ([SW Help: Geometry Status](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_Sketch_Geometry_Status.htm)). IdeaCAD should use the same gray in the viewport and add the word. SolidWorks also allows zero and negative values, a negative value flipping direction ([SW Help: Dimensions](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_dimensions_top.htm)). IdeaCAD's kernel refuses a zero-depth extrude with its own sentence ("Pull the sketch to give it depth."), which is the more honest behavior for an ideation tool. Preview Sketch Dimensions, which shows an entity's dimension on selection so it can be clicked to edit ([SW Help: Previewing Dimensions](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_previewing_sketch_dimensions.htm)), is the Shapr3D pattern done right, because the number stays until dismissed. In 2026, SolidWorks' Modify dialog positions itself so it does not cover the dimension it edits ([SW What's New 2026](https://files.solidworks.com/Supportfiles/Whats_new/2026/English/whatsnew.pdf)). Any IdeaCAD edit box should likewise avoid covering its target. Equations typed with "=" in numeric fields ([SW Help: Chamfers](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_creating_chamfer_feature.htm)) and Shapr3D's variables and expressions ([Shapr3D Help](https://support.shapr3d.com/hc/en-us/articles/18763796906396-Parametric-design-with-variables-and-expressions)) are a later power-user feature (Rigor), worth planning in the parser but not shipping first.

## 8. Selection and interaction: hover must preview, and Esc must always clear

SolidWorks applies one rule consistently: anything that will be selected or changed previews on hover. Dynamic highlighting shows which entity is ready to be selected, with edges as thick lines and face boundaries as thin ones ([SW Help: Highlighting](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_Highlighting.htm)). Breadcrumb hover, Select Other list hover and fillet accelerator icons all preview the same way ([SW Help: Breadcrumbs](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_selection_breadcrumbs.htm); [SW Help: Select Other](https://help.solidworks.com/2025/English/SolidWorks/sldworks/HIDD_SelectOther_dlg.htm)). **IdeaCAD has no hover pipeline in the viewport, and that single missing piece blocks more of this report than any kernel limit does** ([IDEACAD.md](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/docs/IDEACAD.md)). It should be the first interaction investment (Ideation). In a browser, that is a ray cast that keeps all hits instead of the first, and it directly fixes the buried-face problem novices hit constantly.

On selection, a small icon-only context toolbar appears near the pointer with the most frequent actions. Right-clicking shows the same toolbar above a short grouped menu with an expander to the long version. It is a menu, an OK, an "advance to next selection box," a gesture trigger and, in assemblies, a rotate ([SW Help: Accepting Features](https://help.solidworks.com/2025/english/solidworks/sldworks/c_accepting_features.htm); [SW Help: Mouse Gestures](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_mouse_sestures.htm)). IdeaCAD's mouse contract already suppresses the browser context menu inside the viewport ([IDEACAD.md](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/docs/IDEACAD.md)). Right-click should open IdeaCAD's own menu and nothing else, and accept should have a visible button. SolidWorks' Confirmation Corner offers one: OK and Cancel in the viewport corner, Enter for OK, Esc for Cancel, and D to move them to the pointer ([SW Help: Accepting Features](https://help.solidworks.com/2025/english/solidworks/sldworks/c_accepting_features.htm)).

Box selection is where SolidWorks trades novice clarity for expert speed. Left-to-right picks only enclosed items with a solid rectangle, right-to-left also picks crossed items with a dotted one, and a part-mode box picks edges by default ([SW Help: Box Selection](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_Box_Selection.htm); [SW Help: Cross Selection](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_Cross_Selection.htm)). The direction rule is invisible, so IdeaCAD should keep it but label the rectangle live ("inside only" or "touching"). It should also make the default target follow the active tool, edges under fillet and faces under shell (Ideation). IdeaCAD has no rubber-band selection yet ([IDEACAD.md](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/docs/IDEACAD.md)). Selection filters (F5 toolbar, E, X and V one-key filters) change the pointer to a funnel with the filtered entity's icon ([SW Help: Selection Filter](https://help.solidworks.com/2025/English/SolidWorks/sldworks/r_selection_filter.htm)). A hidden active filter is a classic "why can't I click that face" trap, so any filter needs a persistent cursor cue (Rigor-leaning). Previous Selection restores an accidentally cleared Ctrl-built set ([SW Help: Previous Selection](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_previous_selection.htm)). It is cheap and kind.

Command access should come in several paths to the same visible command. SolidWorks' Search Commands (W) filters as you type, shows each tool's shortcut, remembers which result you ran for a query, and can show where the command lives in the interface ([SW Help: Search Commands](https://help.solidworks.com/2025/english/SolidWorks/sldworks/c_command_search.htm)). Enter repeats the last command, and a right-click in empty space lists the last ten ([SW Help: Repeat Last Command](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_repeat_last_command.htm)). Fusion's marking menu fixes Repeat at the top, OK and Cancel on the sides during a command, and Sketch at the bottom, and supports flicks ([Noble Desktop](https://blog.nobledesktop.com/learn/cad/efficient-tool-access-in-fusion-360-marking-menu-toolbox-and-customization)). **Command search with learned ranking is the highest-value single power feature for students, because it rewards knowing the word rather than the location (Both).** Radial gestures are Rigor-leaning expert accelerators and can wait. ## 9. Viewport and display: a labeled cube, a capped section, and round things that look round

Orientation should be one keystroke and one visible control. SolidWorks' Spacebar opens the orientation flyout, and Ctrl+Spacebar shows a view cube around the model. Hovering a face previews that view, back faces are "exploded away" so they can be picked without rotating, and corners select isometric views ([SW Help: Orientation](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_orientation_dialog_box.htm); [SW Help: View Selector](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_view_selector.htm)). Normal To works on a selected face, and "clicking again flips the view 180 degrees" ([SW Help: Normal To](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_viewing_models_normal_to.htm)). Previous View undoes the last ten view changes ([SW Help: Orientation](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_orientation.htm)). The reference triad in the corner rotates with the view, and clicking an axis snaps the view ([SW Help: Reference Triad](https://help.solidworks.com/2025/English/SolidWorks/sldworks/r_reference_triad.htm)). **A labeled cube with hover previews merges the triad and the orientation menu into one discoverable control (Ideation); Spacebar is worth mirroring for students who later move to SolidWorks.** IdeaCAD's mouse contract already matches SolidWorks' navigation: middle-drag orbits about the ray-cast point, Ctrl plus middle pans, Shift plus middle zooms, and the wheel zooms toward the cursor ([IDEACAD.md](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/docs/IDEACAD.md); [SW Help: Keyboard Shortcuts](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_time_saving_keyboard_shortcuts.htm)).

Three display modes cover students: shaded, shaded with edges, and hidden lines visible, which lets students see through a part. SolidWorks' five-way flyout and tangent-edge options (visible, phantom, removed) are the source ([SW Help: Hidden Lines Visible](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_hidden_lines_visible.htm); [SW Help: Wireframe](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_wireframe.htm)). SolidWorks' section view offers up to three planes, a cap with its own color, and a state that persists through save ([SW Help: Section Views](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_section_views_models.htm)). Live Section Planes add a non-modal plane dragged with a triad and ruler ([SW Help: Live Section Planes](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_instant3d_live_section_planes.htm)). IdeaCAD's section is a render clip whose hint says "caps are not drawn" ([SectionPanel.svelte](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/src/lib/ideacad/solid/SectionPanel.svelte)). **The kernel's `section` returns exact cross-section faces that can be tessellated as caps and measured with `faceArea`, so a capped, draggable plane is buildable (Both)** ([Remus d.ts](https://github.com/esaueng/remus/blob/9307e73d880ed824b2b62e44c4a1beb9d5d7b787/crates/wasm/pkg/remus_wasm.d.ts)). A sensible split is GPU clipping while the plane is dragged, then the exact kernel cap on release (inferred). OpenZCAD measured three silent failures on a newer pin that the code must guard against. A plane that misses the body returns an empty array, not an error. A plane flush with a face returns that whole face. A plane parallel to a bore's wall can drop the hole, reporting 120 mm² where the true area is 96 mm², and OpenZCAD checks every exact section against the tessellation's plane crossings for this reason ([OpenZCAD exact section](https://github.com/esaueng/OpenZCAD/blob/3add9e4b8f230479bae866d00036693ce1db6585/packages/kernel-adapter/src/exact-section.ts)). Section also doubles as a thin-wall check for printed parts.

Tessellation quality is display quality: see the size-relative deflection in Section 4. IdeaCAD already computes per-face shading normals, because the shared export mesh averages sharp corners ([IDEACAD.md](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/docs/IDEACAD.md)). The 60 fps target on school integrated graphics remains unmeasured, so display features should be judged against that target. Decline dimetric and trimetric views, multiple and linked viewports, zonal sections, the Y-up or Z-up switch, RealView, cartoon rendering and analysis overlays as Rigor or presentation ([SW Help: Standard Views](https://help.solidworks.com/2025/English/SolidWorks/sldworks/r_standard_views_toolbar_2.htm); [SW Help: View Toolbar](https://help.solidworks.com/2025/English/SolidWorks/sldworks/r_view_toolbar_display.htm)).

## 10. Assembly: name the motion, snap to inferred frames, and let parts modeled in place stay put

SolidWorks builds a joint from several geometric mates, each valid only for certain geometry pairs listed in validity tables. There are three tabs: standard (coincident, concentric, distance, angle, parallel, perpendicular, tangent, lock), advanced (limit, width, path, profile center, symmetry, linear coupler) and mechanical (cam-follower, gear, hinge, rack and pinion, screw, slot, universal joint) ([SW Help: Types of Mates](https://help.solidworks.com/2025/English/SolidWorks/sldworks/r_Types_of_Mates_SWassy.htm); [SW Help: Mates Overview](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_Mates_Overview_Assemblies.htm)). A pin needs concentric plus coincident, and even SolidWorks added Hinge, which has "the same effect as adding a concentric mate plus a coincident mate," partly to reduce redundant mates ([SW Help: Hinge](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_hinge_mates.htm)). Onshape works the other way: "many assemblies require only one Onshape Mate between any two instances," named by motion as fastened, revolute, slider, planar, cylindrical, pin slot, ball or parallel ([Onshape: Mates](https://cad.onshape.com/help/Content/Assembly/mates.htm); [Onshape: Mate Connector](https://cad.onshape.com/help/Content/Assembly/assembly_mate_connector.htm)). **For students who think "this wheel spins on this axle," behavior-named joints fit the no-tutorial goal (Ideation).** IdeaCAD's current mates are six geometric kinds solved in tree order. It already names each body's remaining freedom per axis ("slides along Z, turns about Z") and refuses redundancy in three sentences, including "adds nothing" ([IDEACAD.md](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/docs/IDEACAD.md)). The recommended path is to layer named joints (fastened, revolute, slider, cylindrical, planar, ball) over the existing geometric rows and keep the freedom sentence, which is a better status readout than SolidWorks' "(-)" and "(+)" prefixes ([SW Help 2026: Assembly tree](https://help.solidworks.com/2026/English/SolidWorks/sldworks/c_featuremanager_design_tree_assembly.htm)). Standard kinematics gives the degrees removed: revolute and slider leave one, cylindrical and pin-slot leave two, planar and ball leave three, fastened leaves none ([CADArtifex](https://cadartifex.com/blogs/fusion-360-joints-explained-rigid-revolute-slider)).

Placement should be a drag, not a dialog. SolidWorks SmartMates show a pointer naming the mate that will result and a live snapped preview, and Tab flips alignment. The gesture is gated behind Alt-drag, though, with "release Alt before pressing Tab," and it infers only a few mates. Peg-in-hole, for example, applies concentric plus coincident when a boss meets a hole ([SW Help: SmartMates](https://help.solidworks.com/2025/english/SolidWorks/sldworks/c_SmartMates_Overview_SWassy.htm); [SW Help: Creating SmartMates](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_Creatiing_SmartMates_SWassy.htm); [SW Help: Peg-in-Hole](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_Peg_in_Hole_SmartMates_SWassy.htm)). Onshape infers connector points on hover at face centroids, edge midpoints and cylinder axis ends, and locks one with Shift ([Onshape: Mate Connector](https://cad.onshape.com/help/Content/PartStudio/mate_connector.htm)). Its Snap Mode folds insert and mate into one step: A flips and Q rotates ([Onshape Tech Tip: Snap Mode](https://www.onshape.com/en/resource-center/tech-tips/using-snap-mode-add-mate-parts-assemblies)). **IdeaCAD should make drag-to-snap the default with no modifier, show the joint type at the pointer, and use one key to flip (Ideation).** IdeaCAD already has a magnetic auto-mate during a Move drag, which snaps facing planar faces or parallel cylinder axes within 0.15 in and commits a mate unless Ctrl is held ([IDEACAD.md](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/docs/IDEACAD.md)). Widening it to hover-inferred frames needs the hover pipeline. Fusion's as-built joints "define the relative motion between components without repositioning them" ([Autodesk: As-built joints](https://help.autodesk.com/cloudhelp/ENU/Fusion-Assemble/files/ASM-AS-BUILT-JOINT.htm)). **As-built is the most ideation-friendly pattern for a one-file tool: students model the robot in position, then say "this spins here" (Ideation).** SolidWorks' mate references and magnetic mates are authored connection points that snap a part into place ([SW Help: Mate References](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_Mate_References_Overview_SWassy.htm); [SW Help: Magnetic Mates](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_magnetic_mates_intro.htm)). They map onto a parts library where each wheel, bearing and motor carries its own connector (Section 13).

Coupling mates are worth copying almost exactly. SolidWorks' gear mate needs no teeth and "assigns gear ratios based on the relative sizes of the cylindrical faces or circular edges you select," with an override that turns the box yellow ([SW Help: Gear Mates](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_Gear_Mates_SWassy.htm)). Rack and pinion takes a pitch diameter or travel per revolution ([SW Help: Rack and Pinion](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_Rack_and_Pinion_Mates_SWassy.htm)). Screw couples rotation to translation by pitch ([SW Help: Screw](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_Screw_Mate_SWassy.htm)). Limits bound any distance or angle ([SW Help: Limit Mates](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_Limit_Mates_SWassy.htm)). Mate Controller saves and recalls positions without configurations ([SW Help: Mate Controller](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_assembly_mate_controller.htm)). **For FRC and combat robots, the core set is revolute, slider, gear or belt coupling, rack and pinion, screw and fastened, with limits (Ideation).** Every SolidWorks coupling page carries the same caveat: these mates "do not prevent interference or collisions between components" ([SW Help: Gear Mates](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_Gear_Mates_SWassy.htm)). The interference check in Section 11 should run alongside them. Cam-follower, path, universal joint, symmetry and width are Rigor-leaning and can wait. Remus has no 3D mate solver, so IdeaCAD's own damped Gauss-Newton solver carries all of this ([IDEACAD.md](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/docs/IDEACAD.md)). A coupler is one more equation row relating two existing freedoms.

Moving and instancing complete the set. "You can only move a component within the degrees of freedom allowed by its mating relationships" ([SW Help: Moving a Component](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_Moving_a_Component_SWassy.htm)). SolidWorks adds collision detection with "stop at collision," a dynamic clearance readout, and Physical Dynamics, where a dragged part pushes free parts it touches, with the warning that it "works best... on assemblies that have only a few degrees of freedom" ([SW Help: Collision Detection](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_Collision_Detection_SWassy_probs.htm); [SW Help: Physical Dynamics](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_Physical_Dynamics_SWassy.htm)). Drag-within-freedom with a live minimum clearance should be the default in IdeaCAD, not a mode (Ideation). Physical Dynamics is appealing but should wait for coarse collision (Section 11). Pattern-driven component patterns, where bolts follow a hole pattern, matter for robot frames ([SW Help: Component Patterns](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_component_patterns.htm)). Mirrored opposite-hand parts matter for left and right plates ([SW Help: Mirroring Components](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_mirroring_components.htm)). SolidWorks' exploded views are authored step by step and stored per configuration, and mates cannot be added while exploded ([SW Help: Exploded Views](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_Exploded_Views_in_Assemblies.htm)). An automatic explode that slides parts out along their joint axes gives most of the classroom value with no authoring (Ideation). Step authoring is presentation Rigor. A bill of materials falls out of a one-file model for free by counting part definitions by occurrence, against SolidWorks' separate table feature ([SW Help: BOMs in Assemblies](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_Bills_of_Material_in_Assembly_DocumentsOH.htm)). The kernel's unused `assemblyNew`, `assemblyAddChild` and `assemblyBom` calls could back it (inferred).

## 11. Simulation and analysis: exact geometry checks first, closed-form physics second, FEA only behind a gate

The ranking below weighs value to a student builder against honest browser feasibility. It is this report's judgment, built from the evidence in this section.

| Rank | Feature | Student value | Feasibility | Honesty risk |
|---|---|---|---|---|
| 1 | Interference volume between bodies | Very high | High: kernel intersect plus exact volume | Very low |
| 2 | CG marker, CG height, tip-over angles, per-part mass table | High | Trivial: already computed | Very low, within the density rule |
| 3 | Spinner calculator fed by the model's moment of inertia | Very high for combat | Trivial: closed form | Low if formulas are shown |
| 4 | One-DOF mechanism posing with limits and interference during the sweep | High for FRC arms and linkages | Medium: IdeaCAD's own solver | Low |
| 5 | Clearance and capped section | Medium | High | Very low |
| 6 | FRC quick checks: arm holding torque, drivetrain speed, tip acceleration | Medium to high | Trivial | Low if labeled estimates |
| 7 | Linear static FEA | Medium, often misread | Hard | High |

**Interference is the most honest analysis a B-rep modeler can offer.** SolidWorks' Interference Detection reports the true interference volume, distinguishes "coincidence interferences" from real ones, and can ignore volumes below a threshold. It notes that threaded fasteners generally produce interferences users want to ignore ([SW Help: Interference Detection](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_Interference_Detection.htm)). Remus has no clash API, and its README scope states that measurement is included while stress analysis, collision detection and dynamics are not ([Remus README](https://github.com/esaueng/remus/blob/9307e73d880ed824b2b62e44c4a1beb9d5d7b787/README.md)). The building blocks are all there, though. Run a bounding-box broad phase on every body pair, then `intersectDetailed` or `booleanRegions('intersect', a, b)` on overlapping pairs, then `massProperties(result).volume`, which is exact over the analytic and NURBS surfaces with no tessellation ([Remus d.ts](https://github.com/esaueng/remus/blob/9307e73d880ed824b2b62e44c4a1beb9d5d7b787/crates/wasm/pkg/remus_wasm.d.ts)). `detectCoincidentFaces` gives the separate "touching, zero volume" list, off by default. An "ignore overlaps smaller than X" control handles hairline overlaps in imported vendor parts. Two caveats need regression checks on IdeaCAD's build. The vendored README pins a defect in which `intersect(box, sphere)` keeps the wrong sphere region, and exact tangency and sliver crossings fall back to a mesh path ([Remus README](https://github.com/esaueng/remus/blob/9307e73d880ed824b2b62e44c4a1beb9d5d7b787/README.md)). Clearance comes from `solidToSolidDistance`, which returns the distance and both closest points. Draw it as a dimension line colored against a threshold, such as weapon tip to chassis. During a motion sweep, exact booleans at every pose will likely be too slow in single-threaded WASM. A mesh test per step, with the exact intersect only at the first-contact pose, is the likely design. No browser benchmark was found, so IdeaCAD must measure it. The simulation research cited OpenCASCADE's Boolean specification for the classification logic ([OCCT Boolean spec](https://occt3d.com/dev/doc/overview/html/specification__boolean_operations.html)), but the Remus calls above are what IdeaCAD would actually use.

Mass properties need presentation more than computation. `massProperties` already returns volume, center of mass, the inertia tensor and principal moments and axes at unit density, and IdeaCAD caches everything except the principal axes ([engine.ts](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/src/lib/ideacad/solid/engine.ts)). SolidWorks draws a principal-axes triad at the center of mass and offers a mass override for simplified purchased parts ([SW Help: Mass Properties](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_displaying_mass_properites.htm)). **IdeaCAD's own density rule is the binding constraint here.** Densities come only from MatWeb and Bambu Lab. Printed parts carry an entered or measured total mass, not a density. Center of mass and inertia are computed only when every body's distribution is supported by a uniform stock reference ([IDEACAD.md](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/docs/IDEACAD.md)). A robot with any printed part therefore has a known total mass and an unknown CG. The readout should say which bodies block the CG rather than silently showing nothing. Within that rule, the high-value presentation is a CG marker with a drop line to the ground, CG height as a first-class number, a per-part mass table sorted by weight, and moment of inertia about an axis the student picks. The axis-picked inertia follows from the parallel axis theorem, I_axis = nᵀI_cg n + m d² (standard physics). Show it in both SI and lb·in², because community calculators use the latter ([iRobotics Combots Calculator](https://irobotics.illinois.edu/combots-calculator/)).

**The spinner calculator is the highest-value, lowest-risk simulation for combat builders, because every input except the moment of inertia is a motor or battery spec, and IdeaCAD can supply the inertia no existing calculator can.** Builders currently copy the value by hand from CAD, since the energy formula uses "I = Moment of Inertia (calculated by CAD software)" ([Just 'Cuz Robotics](https://justcuzrobotics.com/blogs/jcr/combat-robot-spinner-design)), and the iRobotics calculator takes it as a typed input ([iRobotics](https://irobotics.illinois.edu/combots-calculator/)). The closed forms are published. Stored energy is ½Iω² with ω in rad/s. Bite is attack speed times 60 divided by RPM times impactor count, and Aaron's example is 88 in/s, 2 teeth and 5,300 RPM for about 0.5 in, with achieved bite averaging half the theoretical value. The energy rule of thumb is a minimum of about 60 J per kg of weight class, with effective weapons near twice that, and at least 45 J/kg within two seconds of spin-up ([Ask Aaron: Spinner FAQ](https://runamok.tech/AskAaron/spinner_FAQ.html)). Tip speed should stay under about 300 mph, ideally 200 to 250. Required kV is the ideal RPM divided by battery voltage, so a 4 in blade at 250 mph on 11.1 V needs about 1,891 kV. Builders typically give 25 to 35% of robot weight to the weapon system ([Just 'Cuz Robotics](https://justcuzrobotics.com/blogs/jcr/combat-robot-spinner-design)). Run Amok models brushed spin-up with a linear torque curve and brushless with reduced low-speed current ([Run Amok help](http://runamok.tech/RunAmok/spincalc_help.html)). The resulting ω(t) = ω₀(1 − e^(−t/T)) with T = Iω₀/τ_stall is standard DC motor physics derived from that description, not a quoted formula. Every output can show its formula on hover, which is the honesty mechanism. The two published worked examples become unit tests. Impact or damage simulation should be declined, because no community tool attempts it and no defensible model exists. Weapons are usually metal, so the density rule rarely blocks the inertia. A printed blade would.

FRC checks follow the same closed-form pattern. The static stability factor is track width over twice CG height, "the lateral G a vehicle can sustain without tipping over" ([Kelvin Tse](https://kktse.github.io/jekyll/update/2022/07/28/trends-in-vehicle-cg-height-and-ssf.html)). A higher CG means the robot tips at a smaller angle ([Chief Delphi: FRC COG](https://www.chiefdelphi.com/t/frc-cog/146107)). Tip angle per support edge, atan(d/h), arm holding torque, m·g·r·cos θ, and drivetrain free speed are standard statics not confirmed against a fetched page, and should be labeled estimates, as ReCalc labels its own calculators "reference only" ([ReCalc](https://www.reca.lc/)). **The uniquely CAD-native check is pose-dependent CG: tip angle plotted across an elevator's or arm's range of travel, which only a model with mechanism posing can compute (Ideation).**

Mechanism motion means kinematic posing, not dynamics. Onshape supports dragging movable instances, animating one mate between start and end values in single or reciprocate mode, and limits drawn as dashed lines. Animation "works with only one degree of freedom at a time" ([Onshape: Mates](https://cad.onshape.com/help/Content/Assembly/mates.htm)). SolidWorks gives every license Animation (keyframes and motors, no physics) and Basic Motion (motors, springs, contact and gravity with mass, "relatively fast"), and keeps Motion Analysis with forces, friction and plots in a Premium add-in ([SW Help: Motion Studies](https://help.solidworks.com/2025/English/SolidWorks/motionstudies/c_introduction_to_motion_studies.htm)). IdeaCAD should drive one joint through its range, re-solve the rest from the previous pose, and stop and flag at solver failure or first contact. A Basic Motion equivalent is a stretch goal. Planar linkages such as four-bars and lifters can be solved as a skeleton sketch whose driving angle is a slider, and the kernel's own 2D `gcs` solver can do that without adding LGPL planegcs (inferred; demand shows in Onshape's community four-bar generator, [Onshape forum](https://forum.onshape.com/discussion/11008/new-four-bar-linkage-generator-featurescript)). Game physics engines approximate joints with drift and are not a substitute for a kinematic solver.

**Linear static FEA is the only feature here with a high dishonesty risk.** SimulationXpress defines the honest scope: a single solid body, isotropic material, fixed faces, force and pressure loads, and stress, displacement and factor-of-safety plots, with safe and unsafe areas in blue and red against a 1.5 default. Its stated assumptions are linearity, elasticity and slowly applied loads, and "results are invalid if these assumptions are not satisfied" ([SW Help: SimulationXpress](https://help.solidworks.com/2025/English/SolidWorks/cosmosxpresshelp/c_overview_of_solidworks_simulationxpress.htm); [SW Help: Results](https://help.solidworks.com/2025/English/SolidWorks/cosmosxpresshelp/c_Viewing_the_Results.htm); [SW Help: Assumptions](https://help.solidworks.com/2025/English/SolidWorks/cosmosxpresshelp/c_Assumptions_of_Linear_Static_Analysis.htm)). Onshape's version adds adaptive refinement with "five adaptive passes," an angular-velocity load relevant to spinner blades, and a requirement that materials supply density, Young's modulus, Poisson's ratio and yield strength ([Onshape: Simulation](https://cad.onshape.com/help/Content/Assembly/simulation.htm)). The only browser FEA core found, SpjutSim, uses Tet10 elements in single-threaded WASM but is unreleased and GPL-2.0-or-later, which would impose copyleft on IdeaCAD ([SpjutSim](https://github.com/Brinkwatertoad/SpjutSim-FEA)). No permissively licensed browser tetrahedral mesher was confirmed. **FEA should ship only behind a validation suite run in CI: a cantilever against FL³/3EI, an axial bar against F/A, and a mesh-convergence check** ([Engineering ToolBox: Cantilever](https://www.engineeringtoolbox.com/cantilever-beams-d_1848.html)). It also needs permanent labels for linearity and ignored stress concentrations, and a warning that printed parts are anisotropic. Onshape's material requirement collides with IdeaCAD's sourcing rule, because every FEA material would need a cited modulus and yield strength as well as a density. The defensible middle ground is a closed-form beam check on a member the student identifies, using the textbook formula and saying so.

## 12. Materials and appearance: color is cheap, but density is a sourcing problem

IdeaCAD already requires a color on every stock material, allows an override from eight named swatches or a hex value, and keeps a strict density rule: a cited material shows its number and its MatWeb link, an uncited one shows an Unverified chip and "Mass: Unknown," and the four cited densities are pinned by a test ([IDEACAD.md](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/docs/IDEACAD.md)). That chip matters more than it looks, because combat builders feed CAD-computed inertia straight into their energy math ([Just 'Cuz Robotics](https://justcuzrobotics.com/blogs/jcr/combat-robot-spinner-design)), so a wrong density silently becomes a wrong weapon energy. SolidWorks sets material by right-clicking Material in the tree ([SW Help: Tree Overview](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_featuremanager_design_tree_overview.htm)). SimulationXpress supports isotropic materials only and warns when yield strength is undefined ([SW Help: Assigning Material](https://help.solidworks.com/2025/English/SolidWorks/cosmosxpresshelp/t_Assigning_Material.htm)). **Any analysis beyond mass needs property sourcing that the current rule does not yet cover, which makes the material catalog, not the kernel, the gating item for FEA (Rigor).** The kernel computes at unit density, so IdeaCAD scales by the cited density, and its units follow the model: in³ for volume and in⁵ for the raw inertia tensor before scaling ([Remus d.ts](https://github.com/esaueng/remus/blob/9307e73d880ed824b2b62e44c4a1beb9d5d7b787/crates/wasm/pkg/remus_wasm.d.ts)).

Appearance should serve identification, not rendering. SolidWorks patterns inherit the seed's color when a single feature is patterned and offer "Propagate Visual Properties" ([SW Help: Circular Patterns](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_Circular_Patterns_Overview.htm); [SW Help: Linear Pattern](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_Linear_Patterns_Overview.htm)). Fusion puts a component color swatch in the timeline so features read by component ([Product Design Online](https://productdesignonline.com/tips-and-tricks/8-fusion-360-timeline-tips-you-must-know/)). **Carry each part's color into its tree and timeline rows, and let instances inherit the seed color, so a twenty-part robot is readable at a glance (Ideation).** SolidWorks' highlight schemes (blue, green, orange) are user settings ([SW Help: System Colors](https://help.solidworks.com/2025/English/SolidWorks/sldworks/HIDD_OPTIONS_SYSTEM_COLORS_fundamentals.htm)). Selection color should be checked against every material color so a selected aluminum face never looks unselected (inferred). RealView, textures, scenes and ambient occlusion are presentation features, and should be declined on the school-GPU budget.

## 13. Add-ons: put domain calculators and parts libraries outside the core

IdeaCAD's add-on contract is already strict. An add-on contributes tools, starters, references and an optional advisory, and its tools can only send the same commands a student's own presses send, a "never restrict" property pinned at the type level. IdeaBlade is the first add-on, with four tools and one starter ([IDEACAD.md](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/docs/IDEACAD.md)). SolidWorks shows the tiering pattern. Motion Analysis needs the SOLIDWORKS Motion add-in in Premium, and a hinge mate in a motion study requires that add-in loaded ([SW Help: Motion Studies](https://help.solidworks.com/2025/English/SolidWorks/motionstudies/c_introduction_to_motion_studies.htm); [SW Help: Hinge](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_hinge_mates.htm)). Onshape's community built a four-bar linkage generator in FeatureScript, which shows demand for mechanism tools beyond the core ([Onshape forum](https://forum.onshape.com/discussion/11008/new-four-bar-linkage-generator-featurescript)). **The spinner calculator, the FRC checks and a four-bar skeleton helper fit the existing add-on shape exactly: each reads the model and advises, and none needs to restrict (Ideation).** Loading them per course keeps the combat panel out of an FRC student's way.

The strongest add-on is a parts library with connectors. SolidWorks mate references let a part carry up to three named mating entities, so dropping it into an assembly finds matching references and mates automatically ([SW Help: Mate References](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_Mate_References_Overview_SWassy.htm)). Since 2025 SP3, AI fastener recognition adds mates to recognized nuts, bolts and washers on insert ([SW Help: AI Fastener Recognition](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_adding_smartmates_ai_fastener_recognition.htm)). Onshape Snap Mode snaps an inserted part's explicit connector to one in the assembly and adds a fastened mate ([Onshape Tech Tip](https://www.onshape.com/en/resource-center/tech-tips/using-snap-mode-add-mate-parts-assemblies)). **A starter library of FRC and combat staples (wheels, bearings, hex shaft, motors, extrusion) with a connector on each part would let students assemble in seconds (Ideation), and it depends on STEP import (Section 14).** Hole Wizard's standard sizes already have a sourced equivalent in IdeaCAD's hole chart. Zoo Design Studio keeps a point-and-click model and a readable code representation in sync, "terse enough for human reviewable version-control diffs" ([Zoo: Design Studio v1](https://zoo.dev/blog/zoo-design-studio-v1)). A readable text view of IdeaCAD's feature list would let teachers diff student work (Rigor), and it is worth keeping in mind as serialization evolves. Macro and API scripting is Rigor, and should be declined for now.

## 14. Import and export: vendor the translator, and scale everything by 25.4

IdeaCAD exports 3MF first, then binary STL, both written from its own cached mesh, plus DXF from sketch or face outlines, and a `.ideacad` backup carrying the original B-rep bytes. It has no STEP ([export.ts](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/src/lib/ideacad/solid/export.ts); [IDEACAD.md](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/docs/IDEACAD.md)). The kernel package holds only a single-solid STEP pair. `toBREP` exports one solid, and `fromBREP` accepts STEP but "multi-solid files will return only the first solid" ([Remus d.ts](https://github.com/esaueng/remus/blob/9307e73d880ed824b2b62e44c4a1beb9d5d7b787/crates/wasm/pkg/remus_wasm.d.ts)). Full exchange lives in a separate translator, `remus-wasm-io`, at the same commit and version 2.130.20, about 2.5 MB of WASM. It provides `exportStep` (AP203, several bodies in one file), `importStep` and `importStepWithReport`, and STL, 3MF, OBJ, PLY and GLB in both directions, with IGES marked experimental ([wasm-io d.ts](https://github.com/esaueng/remus/blob/9307e73d880ed824b2b62e44c4a1beb9d5d7b787/crates/wasm-io/pkg/remus_wasm_io.d.ts); [Remus README](https://github.com/esaueng/remus/blob/9307e73d880ed824b2b62e44c4a1beb9d5d7b787/README.md)). The two packages ship in lockstep, and the build refuses to package them at different versions ([wasm-io Cargo.toml](https://github.com/esaueng/remus/blob/cb13b53f5a40a56e78ae2efd4f7798280e2e0cc2/crates/wasm-io/Cargo.toml)). **STEP is Stable upstream and preserves exact geometry, writing planes, cylinders, cones, spheres and tori as native entities, so vendoring the translator at `9307e73` is the path (Both).** Imports return arena bytes that IdeaCAD's existing `body` feature already restores through `deserializeSolids` and names with `nameImportedFaces` ([core.ts](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/src/lib/ideacad/solid/features/core.ts)). Loading the translator lazily on first import or export keeps it off the first-paint budget (inferred).

The unit trap is concrete. The STEP writer emits millimeters and the reader converts everything to millimeters and radians at parse time ([writer.rs](https://github.com/esaueng/remus/blob/9307e73d880ed824b2b62e44c4a1beb9d5d7b787/crates/io/src/step/writer.rs#L483); [reader.rs](https://github.com/esaueng/remus/blob/9307e73d880ed824b2b62e44c4a1beb9d5d7b787/crates/io/src/step/reader.rs#L505)), while IdeaCAD stores inches. **Scale every solid by 25.4 before export and by 1/25.4 after import, for example with `copyAndTransformSolid`, or files will be 25.4 times wrong (inferred from the writer, reader and IdeaCAD's own export scaling).** A round-trip test pins it. Import errors come back as a bare `Error` with no typed refusal, whether the file is unparseable or over the input budget ([OpenZCAD STEP import](https://github.com/esaueng/OpenZCAD/blob/3add9e4b8f230479bae866d00036693ce1db6585/packages/kernel-adapter/src/kernel-step-import.ts)). The import dialog should therefore translate those errors into student sentences. The default budgets are 256 MiB and three million entities ([Remus README](https://github.com/esaueng/remus/blob/9307e73d880ed824b2b62e44c4a1beb9d5d7b787/README.md)). Whether the translator reads arena documents written by IdeaCAD's vendored kernel was inferred from the lockstep rule, not tested.

Imported parts become editable through direct operations. `resizeBlend` resizes an imported fillet, and `moveFacesJournaled` pushes an imported face, which gives Shapr3D-style editing of geometry with no history (Ideation). Vendor STEP files often carry hairline overlaps with press-fit hardware, which is why interference needs an ignore threshold (Section 11). SolidWorks' Select Partial Loop exists specifically for imported models with many small edges ([SW Help: Partial Loop](https://help.solidworks.com/2025/English/SolidWorks/sldworks/t_select_partial_loop.htm)). That is Rigor, and can wait. On the export side, `projectEdges` produces exact visible and hidden edge sets for a view direction ([Remus d.ts](https://github.com/esaueng/remus/blob/9307e73d880ed824b2b62e44c4a1beb9d5d7b787/crates/wasm/pkg/remus_wasm.d.ts)). A hidden-line SVG or DXF view for notebooks is therefore cheap, the same capability Plasticity added in 2026.1 ([Plasticity 2026.1](https://doc.plasticity.xyz/release-notes/whats-new-2026.1)). Upgrading the kernel does not change this area: the translator's API is identical at upstream HEAD, and the kernel adds only three methods over 926 commits ([Remus d.ts at HEAD](https://github.com/esaueng/remus/blob/cb13b53f5a40a56e78ae2efd4f7798280e2e0cc2/crates/wasm/pkg/remus_wasm.d.ts)). IdeaCAD's provenance notes forbid swapping the binary without verifying saved-document round trips ([PROVENANCE.md](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/src/lib/ideacad/kernel/vendor/remus/PROVENANCE.md)).

## 15. Learning and personalization: teach at the moment of need, and let every hint come back

The evidence argues against a first-run tour. NN/g's position is that "tutorials interrupt users, don't necessarily improve task performance, and are quickly forgotten," and that help should instead be pulled by contextual signals, easy to dismiss and retrievable later ([NN/g: Onboarding Tutorials](https://www.nngroup.com/articles/onboarding-tutorials/)). Coach-mark overlays get dismissed because short-term memory "fades in about 20 seconds," and several tips in a row make an app seem "overly complicated and daunting" ([NN/g: Instructional Overlays](https://www.nngroup.com/articles/mobile-instructional-overlay/)). The strongest controlled result is Autodesk Research's ToolClips, tooltips extended with 10 to 25 second video clips. AutoCAD novices completed 70% of tasks with ToolClips against 10% with traditional help, and completion time a week later dropped from 306 s to 166 s ([Grossman and Fitzmaurice, CHI 2010](https://www.tovigrossman.com/papers/chi2010toolclips.pdf)). **IdeaCAD should teach through the empty canvas, hover and focus help on every tool with short looping demos, and one hint at a time on first encounter with a tool (Ideation).** SolidWorks has offered large tooltips with images or short animations since 2020 ([SW What's New 2020](https://help.solidworks.com/2020/English/WhatsNew/r_enhanced_tooltips_wn.htm)). Fusion users complained that rich descriptions disappear "too fast to read" ([Autodesk Community](https://forums.autodesk.com/t5/fusion-design-validate-document/display-of-feature-tool-detailed-description-disapears-too-fast/td-p/5934835)). The timing guidance answers that: show after 0.3 to 0.5 s, hide more than 0.5 s after the pointer leaves, and tolerate movement into the tooltip ([NN/g: Timing](https://www.nngroup.com/articles/timing-exposing-content/); [ToolClips](https://www.tovigrossman.com/papers/chi2010toolclips.pdf)). Tooltips must also trigger on keyboard focus, and must never hold the only copy of essential information ([NN/g: Tooltip Guidelines](https://www.nngroup.com/articles/tooltip-guidelines/)).

An optional tutorial can still be a differentiator if it runs in the real canvas and advances when the student actually performs the action. A 2024 Tinkercad critique called the official lessons "painfully slow" after "the first 10 'Nexts'" and argued that software "should be self-guiding" ([jackbellis, Medium](https://jackbellis.medium.com/keys-to-learning-tinkercad-4e00d3b4fd80)). That is a single author's opinion, but it argues for action-triggered steps and a visible exit at every step. Shapr3D users asked for onboarding that can be replayed ([Shapr3D Community](https://discourse.shapr3d.com/t/reset-onboarding/4504)), so the tutorial should live behind a persistent Learn control. Progressive disclosure should stop at two levels: frequent tools visible, everything else one clearly labeled step away or in command search, because designs "rarely succeed beyond 2 disclosure levels" ([NN/g: Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/)). Grossman's learnability taxonomy names five problems: task flow, awareness, locating, understanding and transitioning to efficient behavior ([Grossman, Fitzmaurice and Attar, CHI 2009](https://www.tovigrossman.com/papers/2009%20chi%20learnability.pdf)). Each can be mapped to a mechanism. Command search that highlights the real button covers locating, as Blender's F3 search shows each result's menu location ([Blender Manual: Search](https://docs.blender.org/manual/en/2.90/interface/controls/templates/operator_search.html)). Hover demos cover understanding. A "you did that the slow way, try this" nudge covers transitions. Figma UI3's toggle that shows property labels "for learning purposes" and hides them once confident ([Figma Blog: UI3](https://www.figma.com/blog/making-the-move-to-ui3-a-guide-to-figmas-next-chapter/)) is a cheap Ideation adopt. Hints should retire after a tool has been used successfully a few times and remain findable in a tips list, per NN/g's later-retrieval rule.

Personalization should live in an account-level settings document. SolidWorks stores almost every interface choice per user, exports them through its Settings Wizard, syncs them through Synchronize Settings, and lets administrators lock options ([SW Help: Settings Wizard](https://help.solidworks.com/2025/english/solidworks/sldworks/c_solidworks_settings_wizard.htm); [SW Help: Synchronize Settings](https://help.solidworks.com/2025/English/SolidWorks/sldworks/r_synchronize_settings.htm)). The browser equivalent is exportable JSON with reset per scope, plus a teacher-distributed default profile so a class starts identical (Both). SolidWorks scopes customization separately per document type and mode ([SW Help: Customize Toolbars](https://help.solidworks.com/2025/english/SolidWorks/sldworks/hidd_customize_toolbars.htm)), which is an expert benefit and a confusion source, so IdeaCAD should show one unified editor. Density should offer two or three named levels previewed instantly, as Gmail has since 2011 ([Gmail Blog](https://groups.google.com/g/gmail-blog-posts/c/CTvQcH69O-I)). Compact changes spacing and label visibility, never hit targets below 24 px, the WCAG 2.2 AA minimum ([W3C: SC 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)). The pathway's interface standard sets 44 px on student surfaces, which matches the AAA level. A reduced-motion override covers demo clips, tutorial spotlights and playback ([W3C: SC 2.3.3](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)).

## 16. Branding and chrome: chrome should follow the pointer and the selection

SolidWorks keeps a dense professional interface without dead space by putting commands where the pointer already is and hiding everything else until context calls for it. It uses one tabbed CommandManager instead of many toolbars, with standalone toolbars "turned off by default," a transparent heads-up view toolbar over the viewport, flyout groups, menus hidden behind the logo until hovered, short-by-default shortcut menus, and context toolbars and breadcrumbs that appear only on selection ([SW Help: CommandManager](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_commandmanager.htm); [SW Help: Toolbars](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_toolbars.htm); [SW Help: Menus](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_menus.htm); [SW Help: Graphics Area](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_graphics_area_solidworks.htm)). **The principle to adopt is that persistent chrome stays minimal (tool strip, tree, properties) and transient chrome appears at the point of attention and vanishes on Esc (Ideation).** One SolidWorks trick should be declined for novices. Some flyouts make "the last used command... the button icon," so the icon changes under the user ([SW Help: Flyout Buttons](https://help.solidworks.com/2025/English/SolidWorks/sldworks/c_flyout_tool_buttons.htm)). Fixed icons are more learnable.

Figma UI3 is the modern reference for a canvas tool. It moved tools to a bottom toolbar to free canvas space, made panels resizable, and added Shift+\ to minimize the UI and Cmd or Ctrl+\ to hide it ([Figma Blog: UI3](https://www.figma.com/blog/making-the-move-to-ui3-a-guide-to-figmas-next-chapter/)). Reports that Figma shipped floating panels and returned to fixed ones after beta feedback are unverified ([Figmalion #184](https://figmalion.com/issue/184)). The cautious call is still fixed panels. At narrow widths, the priority-plus pattern keeps the most important tools visible and moves the rest to an overflow control, which is clearer than a hamburger menu ([Brad Frost: Priority+](https://bradfrost.com/blog/post/revisiting-the-priority-pattern/)). IdeaCAD's tree already becomes a slide-over at 375 px ([IDEACAD.md](https://github.com/pina-hash/idea-app/blob/1ec2f6402cb1861d6e96b6fd959a5927c937ea2d/docs/IDEACAD.md)). For the mark itself, no authoritative source sets rules for animating a product logo inside an app, so the applicable limits come from WCAG and institutional motion guides. Hover-triggered motion should be able to be disabled, and an opacity or color change does not count as motion ([W3C: SC 2.3.3](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)). A loop longer than five seconds needs pause, stop or hide ([W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/)). A flourish runs 200 to 500 ms with ease-out for user-triggered motion, and nothing flashes more than three times per second ([ASU Brand Guide: Motion](https://brandguide.asu.edu/execution-guidelines/web/ux-design/animation)). **A short ease-out flourish on load or hover that swaps to an opacity change under reduced motion satisfies all of them (Ideation).** The mark's visual identity belongs to the pathway's design standard, which this research did not read.

## Conclusion

The research changes where the risk in IdeaCAD sits. The obvious worry for a browser B-rep tool is the kernel, and the evidence says the kernel is ahead of the interface. Remus already carries exact mass properties, typed fillet refusals that state the largest radius that fits, blend resizing, exact sections, hidden-line projection and a STEP translator. Most of what it lacks (face-face fillets, vertex chamfers, setbacks, guide-curve lofts) is what SolidWorks itself keeps for industrial designers. The gaps that actually block the "faster than SolidWorks, no tutorial" goal are two missing pieces of IdeaCAD's own viewport, a hover pipeline and dimension text drawn where it can be clicked. They are worth building before any new feature, because they unlock dozens of mechanics at once. The second shift is that honesty, not physics, shapes simulation. The exact checks (interference, clearance, sections) need no disclaimer. The closed-form calculators earn trust by showing their formulas. The density rule already turns "center of mass" into a question of which bodies are sourced, and FEA is gated by a license and a material catalog before any solver question arises.

Two design bets follow that no competitor documented. First, a one-file model with per-part histories and definition-versus-occurrence instancing is the only arrangement that keeps both the replay cost and the BOM honest, and it lets IdeaCAD adopt Fusion's as-built joints without Fusion's body-to-component conversion step. Second, the time-lapse should treat the feature list as structure and the operation log as process. Playing cached meshes from either gives a scrubbable, shareable record of how a student reached a design, which no fetched CAD tool offers and which doubles as the engineering-notebook evidence a classroom already asks for. Every construction this report marks as needing a spike (rib, full round, curve joining, split-line draft, translator compatibility) should be measured on `remus-9307e73` before a lane depends on it, and each silent failure OpenZCAD measured on its newer pin deserves a regression test on IdeaCAD's build.

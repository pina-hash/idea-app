## What changed

- **0310** (on main in `2c693f7e`, applied in `566a75ff`): `armory_devices.computer_key`,
  nullable, checked against the `armory_app_incidents.machine_id` rule; additive four-argument
  `armory_heartbeat` and three-argument `armory_register_device`, the old forms thin wrappers
  passing null; `armory_team_status` adds `computer` per device, `left(md5(project || ':' ||
  key), 12)`, so the raw key never leaves the database and one computer reads differently in two
  projects. The visible set of devices and who may read them did not move (`armory_can_view`).
- **Website** (`src/lib/armory/team.ts`): `computerKey` is the one statement of the grouping
  (token, else lowercased name, else device id; a keyed and a keyless device never together).
  `computerGroups`, `presenceDevices` (one member's lines), `teamComputers` (the new Computers
  list under the Team view, everyone on each computer, most recent first) and
  `labelProjectDevices` (Files and Checked out labels) all go through it. `deviceLabels` now
  labels per computer: every sign-in on one keyed computer shares one label, and two computers
  sharing a name read "NAME (abcd)" from the token; a keyless device keeps its device-id label
  exactly as before.
- **Armory 0.5.1** (idea-armory): each team heartbeat carries `MachineId.Current`, the same
  per-computer hash the incident file sends as `machineId` (MachineGuid plus the computer's own
  network address). A 404 PGRST202 on the four-argument form resends the same beat without the
  key and offers the key again after six hours; a key outside the server's rule is never sent.

## Load-bearing decisions

- **An opaque per-project token, not the key.** The key is stable across projects; returning it
  would let a member of two projects link a computer between them. The md5 prefix is enough to
  group within one read and to label.
- **Keyed and keyless are never merged.** During the changeover a shared computer can show one
  line from 0.5.1 sign-ins and another from older ones; merging by name would fold two cloned
  computers into one, which is the bug the key exists to fix.
- **Registration sends no key.** Both callers (the website connect flow and the app's sign-in)
  keep the two-argument form; the first 0.5.1 heartbeat writes the key seconds later. That keeps
  the connect flow untouched and the deploy order-free.

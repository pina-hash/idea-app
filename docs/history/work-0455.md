### What was wrong, measured

- **"UPDATE requires a WHERE clause" (c940fc00) and "seeding is completely broken" (6aa5ba19) are one
  bug.** The message is pg-safeupdate's, which the hosted project loads for API requests. A string-aware
  scan of every migration for an UPDATE or DELETE with no top-level WHERE found two in a runtime
  tournament function: `_tournament_qual_seed_order` (0062) fills its `pg_temp._t_standings` with
  `update ... set wins = (...), ...` and `update ... set win_pct = ..., rand_key = random()`. Only a
  tournament with qualifying pools reaches it, from `tournament_generate_bracket`, which is exactly the
  IDEA-Blade Rotation 2 case (2b5723ca, Oct 27); unseeded tournaments always worked, which is why the Oct
  27 chat could rebuild without pools. The fixture loads no extension, so no db suite could see it. The
  same scan found six more outside this lane, all left alone and listed here for whoever owns them:
  0009 and 0118 (one-time migration bodies), 0237 `foundry_featured_set`'s `delete from
  public.foundry_featured` (a runtime function an admin calls: it will fail the same way), and 0283's
  one-time relaunch block (three deletes, two updates).
- **The format locked at generation (544604c9).** `tournament_update` refused any config once `live`.
- **Typing an email every time (c6830880).** The invite, co-host and teammate rows were bare address
  boxes; no tournament-scoped directory existed (Armory and Foundry each have their own).
- **The connector refusing tournament reads (d4c2b43e).** Reproducing it from this session was refused by
  this session's own permission layer, so the cause is from the code and the Oct 27 chat: the only
  tournament read the connector had was `tournament_reward_settlement`, a public read of whether coins were
  paid, which says nothing about setup, and the chat had no read of format, entries, seeds or pools at all.
  `tournament_generate_bracket` was reachable only as a generated tool, and the four live-operation
  functions it generated (`tournament_submit_match_result`, `tournament_correct_match_result`, the reset)
  were offered against Mr. Pina's standing rule.
- **Copy forward did not exist in any form (3a549386)**, and **a duplicate dropped pacing and checkpoints
  (64441b57)**: `_classroom_duplicate_work_surface` (0298) predates `classroom_item_pacing` (0308) and
  `classroom_signoff_checkpoints` (0304) and copied neither.

### What landed

- **0317** `supabase/migrations/0317_tournament_bracket_seeding_and_format.sql`: the two WHEREs (the
  primary key, true of every row); the seed write in the bracket generator as one statement;
  `tournament_update` taking new lengths while live with no result (`_tournament_has_result`: a match
  started or decided between two entries, or a game recorded; a bye is not a result), re-stamping every
  unplayed match and logging a `corrected` event, qualifying, scoring and team size held; reads
  `tournament_setup_state` and `tournament_list_admin`; the directory `tournament_people_search`.
  Signatures unchanged or new, so the deploy and the apply land in either order.
- **0318** `supabase/migrations/0318_classroom_copy_forward.sql`: `_classroom_shift_school_day` (the one
  date rule), `_classroom_copy_post_extras` (pacing rows and checkpoints, shifted or not), 0298's work
  surface copy calling it (so `classroom_duplicate_item` and the connector's `duplicate_post` carry both),
  `classroom_copy_forward_preview` and `classroom_copy_forward` over one plan. A copy IS a duplicate (the
  0298 function, stated once), then given the source's title, unit (same id, or the same name in another
  course), order, pin and shifted dates; a post already shared across classes is shared, never copied;
  copies are drafts, and `p_publish` schedules a published source on its new day while a draft stays one.
  `classroom_copy_forward_log` keeps a second run from copying twice.
- Host console: the format card offers the lengths while nothing is played (`bracketHasResult`,
  `LENGTHS_ONLY_LOCK`), with a degrade for an admin on a database without 0317; `PersonPicker` on invite,
  co-host and the teammate row (which also fills the roster name), a typed address still accepted.
- Class page: "Copy to class" beside Units opens `CopyForwardPanel`: class, first class day, Preview
  (every post, what happens, old and new due date), one Copy.
- Connector: `tournament_setup_state`, `tournament_list_admin`, `tournament_people_search` (reads),
  `tournament_generate_bracket` (asks first, the last setup step); the live-operation functions excluded
  with his rule as the reason; `classroom_copy_forward_preview` (read) and `classroom_copy_forward` (asks
  first), with samples in `tests/db/connector-samples.ts`.

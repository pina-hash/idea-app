A blade that exists only in a canvas is not yet a part. This bundle adds a pure,
unwired export boundary: every public function takes ordinary data and returns a
`Uint8Array`; none reads the DOM, starts a download, or owns application state.

## One mesh, not two plausible blades

`evaluatedBladeTriangles` calls `evaluationGeometries`, the same factory the
viewport calls, and reads the blade `BufferGeometry` it returns. The exporter
does not repeat the sketch mathematics or extrusion. It converts the factory's
inch coordinates to millimetres while preserving its triangle order, then
disposes all four geometries the factory allocated.

`exportBinaryStl(evaluation)` writes that triangle soup as binary STL with the
normal calculated from the ordered vertices. The round-trip test parses every
50-byte facet back out, matches triangle count and all three bounding-box axes
to the source factory, checks every normal points with its winding, checks
positive signed volume, and counts undirected geometric edges. Every edge in
the measured default blade is used exactly twice.

`exportThreeMf(evaluation, name?, color?)` packages the same triangles as a 3MF
core model. Its model declares `millimeter`, carries one base material with an
explicit display colour, and is put in a deterministic store-only ZIP with the
required content-types and root relationship entries. Store-only ZIP was chosen
over adding a compression dependency: the generated blade is small, the package
is interoperable, and the pure byte contract remains usable in browser and
server runtimes.

## The laser path is the evaluated profile

`exportBladeDxf(evaluation)` writes one `LWPOLYLINE`, closed through DXF flag 1,
on the `BLADE` layer. `$INSUNITS` is 4 (millimetres), and every evaluated outline
coordinate is converted by exactly 25.4. The test parses group-code pairs back
from the bytes, finds the entity rather than searching for incidental text,
asserts its closed bit and vertex count, and matches both planar extents to the
evaluated blade polygon.

## Traceability and the later wiring seam

`exportManifest(evaluation, { partName, material, stockThicknessMm })` writes a
versioned UTF-8 JSON record with the part name, evaluated mass, material, stock
thickness and a snapshot of every rule's id, label, value, limit and pass result.
The caller supplies the human-readable material and resolved thickness because
`Evaluation` deliberately does not carry those catalogue fields.

A later button bundle imports these exact four functions from
`$lib/ideacad/export`: `exportBinaryStl(evaluation)`,
`exportThreeMf(evaluation, partName, color)`, `exportBladeDxf(evaluation)`, and
`exportManifest(evaluation, manifestInput)`. It owns filenames, Blob creation,
download gestures and any decision to bundle files; this layer owns none of
those browser concerns.

## Boundaries and verification

This exports one blade per file, not the circular pattern or rotor body. That is
the independently cut sheet part represented by the viewport's blade mesh and
the one-part-per-DXF requirement. No UI, viewport, route, state module, stored
tree, evaluator, geometry factory, dependency or migration changed.

The repository-wide checks retained the known unrelated IdeaCAD UI mount
failures and existing type-check errors. The export round-trip test itself is the
measurement for generated bytes; it does not claim a physical slicer or laser
controller import was performed in this container.

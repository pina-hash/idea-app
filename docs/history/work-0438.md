**0311, an edit names its fields.** `classroom_update_item` gains `p_fields text[]`
(default null). Null is a full edit, exactly the old behaviour, so the post editor
(`/api/classroom/item`) and `classroom_restore_revision` are untouched; given, only the
named fields change. PostgREST cannot tell an omitted argument from a null one, which is
why the function could not infer it. The old ten-argument form is dropped first so a call
naming neither form is never ambiguous. The connector's `fill: fields` argument kind
(`registry.ts`, `siteCallEntry`) fills the list with the arguments the call gave, other
than the record it acts on. The migration shipped alone with `p_fields` given a spoken
name but no fill, so nothing could send the new parameter before production had it; the
fill followed after Migrate's record. Undo: re-run 0176's block after dropping the
eleven-argument form (written in the file).

**0312, presentation lists.** Two tables with RLS on, no policy and no client grant; every
read and write is a definer function that asks `classroom_manages_section` first, so
"not yours" and "not there" are one answer. Notes and scores are NOT new write paths: a
note is `classroom_feedback_post`, a score is a held `classroom_grade_submission` or
`classroom_grade_team`.

**Both grade writes replace a whole grade, and that is a trap for any partial writer.**
`classroom_grade_submission` sets `rubric_scores`, `criterion_comments` and
`teacher_comment` from its arguments wholesale. The phone page's first version sent only
the tapped rows with a null comment, which would have wiped every other row and the
written comment. `createPresentationScoring` now reads the stored grade and sends it back
under the tapped rows; `teamScorePlan` does the same for a team and refuses when members
carry different comments, because `classroom_grade_team` writes one comment to all. This
is the same shape as the 0311 bug, found before it shipped.

**Connector shape for presentations.** Hand entries in `registry/classroom.yaml`,
the two tables added to `SYNCED_LOG_TABLES` (a write whose rows land in an unlisted table
reads as writing nothing), samples in `tests/db/connector-samples.ts`. Start is `confirm`,
not `undo`: closing the new list leaves its entries (a closed list is a record) and does
not reopen the one it replaced, so it is not a true reverse.

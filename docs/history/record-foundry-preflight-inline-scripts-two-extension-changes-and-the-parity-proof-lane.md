## Foundry preflight: inline scripts, two extension changes, and the parity proof (`lane/foundry-inline-scan`)

No migration. Three items, and the third closed a gap the previous lane
reported as unverifiable.

### Inline `<script>` blocks are scanned

`scanJs` only ever read `.js` files. A single HTML file is now a first-class
submission shape and in that shape ALL the JavaScript is inline, so every JS
rule was doing nothing for what will be the most common upload. `scanHtml` now
feeds the body of every `<script>` without a `src` to the SAME scanner, with a
line offset; the ones carrying a `src` are already judged as references and are
left out so nothing is reported twice.

The offset is a parameter rather than a second scanner, and it moves the number
INSIDE the sentence rather than only the `line` field -- the messages are built
from `where(path, line)`, so correcting the field alone would leave a student
reading a number and looking at the wrong line.

Two things that would have been silent:

- **CRLF.** An HTML parser normalizes CRLF to LF in the DOM, so on a file saved
  by a Windows editor the text the parser hands back is not a substring of the
  source and every lookup returns null. Both sides are stripped of carriage
  returns before the search; line numbers are counts of `\n`, so that cannot
  move one.
- **A PRE-EXISTING OFF-BY-ONE, WHICH WAS ALSO WRONG IN `.js` FILES.** The
  patterns open with `(?:^|[^\w$.])` so `prefetch` and `this.fetch` do not
  match, which makes the match START at the character before the call -- and at
  column 0 that character is the previous line's newline. Measured on a plain
  `.js` file: a `fetch` on line 3 answered "app.js line 2". Statements at column
  0 are most of the statements anybody writes. Found because a fixture written
  for the inline case disagreed with the arithmetic; fixed in the shared module,
  so both sides moved.

### `.ico` allowed, `.md` ignored

`FOUNDRY_IGNORED_EXTENSIONS` is a third category beside allowed and refused:
dropped on the way in with a note, exactly as `isOsNoise` is. `.md` is its only
member. `.ico` simply joined the allowlist with a real content type.

The line between ignored and refused is that dropping the file must change
nothing about the app. A `.ts` or `.scss` is a SOURCE file and a bundle carrying
one means the student shipped the wrong folder -- that stays a refusal, because
the refusal is the thing that tells them.

The contract's vague paragraph is gone. It read "Do not produce a README, a
package.json, a lockfile, a config file, or a build script. They are not used
and several of them are refused." It was vague and also WRONG: `package.json`
and `package-lock.json` are `.json`, which is on the allowlist, so they upload
happily. It is now generated by putting each candidate through the SAME
predicates the upload uses and sorting by what actually happens, so it cannot
claim an outcome the code does not produce.

### The parity proof, run for real

The previous lane reported Docker and Deno as unavailable and left the
browser-versus-deno-dom question open. **That was wrong**: Docker and the
Supabase CLI are in WSL, and `supabase status` from the Windows side cannot see
a WSL stack, which is what made it look otherwise. The check is `wsl docker ps`.

A stack for another project (`fll-app-sk`) was already running on the 543xx
defaults. `supabase/config.toml` here is deliberately shifted to 544xx, so
`idea-app` came up beside it with no conflict and that stack was not touched;
only `idea-app` was stopped afterwards.

Five fixtures were built once and driven through BOTH paths -- the browser
preflight in a real browser via a dev-harness hook, and the real
`foundry-ingest` on the local stack with a real user, a real storage object and
a real version row. **10 messages, 5 fixtures, 0 differences, byte for byte.**

The freshness marker matters as much as the result: `.md` and `.ico` were
included specifically because their answers CHANGED in this lane, so the new
note coming back proves the edge runtime was serving the edited module rather
than a cached one.

The awkward-markup fixture is the one that answers the actual question:
unquoted attributes (`<img src=/art/unquoted.png alt=Logo>`), an unclosed
`<div>` and `<b>`, a bare `>` in prose, a URL inside an HTML comment, and an
attribute on its own line. deno-dom and the browser's DOMParser agreed on all of
it -- including correctly NOT reporting the URL in the comment, and reporting
the wrapped attribute at the line the VALUE sits on rather than the line the tag
opens on.

### Verified

`svelte-check` 0/37 at the documented mix. Full suite 98 files, 2309 tests. The
three input shapes re-driven through `/dev/foundry-submit`, with the
single-HTML fixture now carrying an inline `fetch` -- which earns a warning at
line 12, and earned nothing at all before this lane.

### NOT verified

- **The line-offset fallback for a block that cannot be located.** It uses the
  last known start rather than zero, which is the honest behaviour when the
  needle is missing, but no fixture reaches it: every parser tested returns
  script text that is a literal substring of the source.
- **Nothing ran against the production project.** The parity work used the local
  stack; the deployed function has not been re-invoked.

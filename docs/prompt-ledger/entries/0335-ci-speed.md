- Notes: The biggest cost was not the serial run. It was the checkout. `fetch-depth: 0` fetched all 98 agent branches, and `tools/idea-status.py` runs one `git show` per ledger entry per branch. So three test files took 596 s of the 1,102 s suite (run 36343240552's own log timestamps). On one machine, `deploy-probe-cli` took 647 s with every branch fetched and 40 s with `main` + `integration` only. CI is now four jobs. `scope` decides full or docs-only and runs the document checks. `check` runs shallow. `test` is sharded 5 ways with `fail-fast: false`. `ci` fails unless every part that had to run passed. Every job fetches only `main` + `integration` history. `--shard` would have split the isolation-proof pair at every N from 3 to 10; with vitest's own split, shard 5/5 failed `db-isolation-b` locally. `tests/db/sequencer.ts` now keeps the pair together. The docs-only path runs the 42 test files that name a document or a tool (`--docs-only`, three processes). A branch is judged against its merge base with `main`, never against its last push alone. Otherwise, once the cancel killed a code push's run, a ledger-only push would read green over untested code. The path is also refused when code under `src/` names a changed document: `mdm-content-seed.md` is imported as FRC page content, and a `docs/` CSV is read through a `src` constant. An fs-tracing run found both. Before: a median of 19.4 min (router's figure); 19m47s and a 1,103 s test step on run 36343240552. After, measured locally: 5 shards took 136 to 198 s of vitest each (three at a time, traced), and docs-only took 81 s of vitest at three processes. CI wall times after the push are in the session report, not measured here. Not built: file parallelism inside a shard (not proven safe: the DB stub's `create role` guards race), and booting Postgres only for DB files (213 files use it, most outside `tests/db/`). Follow-up for `integrate.yml`'s owner: its merged-suite job still checks out `fetch-depth: 0` and pays the same ~490 s. `tests/git-refs-precondition.ts`'s refusal message still says `ci.yml` uses `fetch-depth: 0`.
